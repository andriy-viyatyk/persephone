**Status:** Active
**Created:** 2026-09-07

## Overview

Today the application's documentation exists twice and lives in the wrong place. `docs/` (32 files,
~11.7k lines) is a GitHub folder the user has to leave the app to read; `assets/mcp-res-*.md`
(12 files) is a parallel agent corpus reachable only through MCP resources — a protocol step some
models never take. The two corpora describe the same application, and in places (`docs/editors.md`
at 931 lines vs `assets/mcp-res-ui-editors.md`) catalogue the same screens in different words.

This epic makes them **one corpus at one path**, `assets/guides/`, with front matter saying which
audience each page serves, and puts it on the surface every agent already uses: a `guides` root node
in the `call` tree, served by the main process, with paths, a tree, and full-text search. The twelve
MCP resource URIs keep working, served from the new files.

**It is deliberately a move, not a rewrite** (roadmap principle 2). The diff must show the same
text at a new path, so the review can concentrate on the loader, the node and the search rather than
on prose. Merging the duplicate editor catalogues, splitting `editors.md` per screen and writing the
`## Layout` schemas are EPIC-094's work and are out of scope here — including the temptation to
"just fix" a paragraph while moving it.

## Goals

- `assets/guides/` exists as the roadmap's tree, containing every page from `docs/` (15 root pages, 16 API pages, one JSON fixture) and all twelve
  `assets/mcp-res-*.md` files, moved verbatim with `git mv` so history follows the text.
- Front matter (`title`, `audience`, `summary`, optional `editorId`) on every page; the tree is
  generated from the files, with no manifest to keep in sync.
- A shared guide index module, `src/shared/guides/`, that parses front matter, builds the tree,
  looks a page up by path, and searches full text returning passages with their page path — title
  and heading hits ranked above body hits.
- A `guides` root node served by the **main process**, so `guides.*` answers even when the renderer
  is busy or the window is closed.
- The twelve `persephone://guides/*` resources re-pointed at the new files with **unchanged** URIs,
  names and descriptions; `persephone://guides/full` concatenating the `agent` and `both` pages.
- `SERVER_INSTRUCTIONS`, the `call("")` overview, and the `ui`/`editors` node help sending agents to
  `guides` paths first, resources only as an alternative.
- `docs/` still works for anyone reading on GitHub (stubs), and every in-repo pointer that would
  break is re-pointed.
- The QA gate passes: a fresh Haiku agent with `call` as its only tool answers the guide questions
  from `guides.*` **without reading a resource**.

## Decisions recorded

1. **Root name: `guides`.** Already reserved at the root
   (`src/renderer/scripting/ai-vision/root.ts`, `RESERVED_ROOT_NAMES`, where it is marked "owned by
   later tasks") and already the word the twelve resource URIs use. One word, already promised, and
   the corpus is not user-only, so `userGuide` would misdescribe it. `userGuide` remains the user's
   working name; if they prefer it, it is a rename in one descriptor plus the overview line — see
   **Needs user check**.

2. **Front matter per page, not `manifest.json`.** Roadmap default, taken. One source of truth per
   file: a page's title, audience and summary travel with the page, so a moved or renamed page
   cannot drift from an index, and nothing has to be edited twice. The tree is generated by
   `src/shared/guides/`. YAML-ish front matter also renders acceptably on GitHub, which is the only
   reason a manifest was considered. The manifest stays the fallback and is not built now.

3. **`git mv` plus `docs/` stubs, not copy.** The move must carry history — this text is years of
   accumulated user documentation and `git log --follow` on it is worth more than the convenience of
   leaving `docs/` intact. So the files move, and `docs/index.md` and `docs/api/index.md` are
   replaced by short stubs pointing at `assets/guides/`. That keeps `README.md`'s Documentation
   block and any external link to `docs/` from 404ing between now and EPIC-095, which deletes
   `docs/` outright. The stubs are the only new prose this epic writes.

4. **Front-matter shape.** `title` (string), `audience` (`user | agent | both`), `summary` (one
   line, shown in the tree and in `guides` hints), and `editorId` on screen pages that document an
   editor. Delimited by `---` lines at the top of the file. The first-line breadcrumb
   (`[← Home](./index.md)`, present on every `docs/` page but `index.md`) is **removed** — the tree
   and the browser render breadcrumbs from the path — and that removal plus the front matter is the
   *only* content change permitted in the move.

5. **Audience assignment.** `formats/*` (notebook, links, graph, ui-push) and `agents/*` (the
   ex-`mcp-res-*` pages: overview, boards, tools, mneme, mcp-setup, agent-tools, browser, pages,
   scripting) are `audience: agent`. Installation and getting-started are `user`. Everything that
   describes a screen or a feature both readers use is `both`. Where an ex-`docs/` page and an
   ex-`mcp-res` page cover the same ground, **both files move** and both keep their audience —
   merging them is EPIC-094.

6. **`docs/examples/greek-gods.fg.json` moves to `assets/guides/examples/`.** It is a sample file,
   not documentation, and the standing fixture rule forbids deleting it. The one link to it is in
   `docs/editors.md:403` (not the graph guide, as first assumed) and is re-pointed with the move.

7. **The API reference (`docs/api/*`, 16 pages) moves unchanged** to
   `assets/guides/scripting/api/`, `audience: user`. Whether it survives long-term is a question for
   after EPIC-095 (scripters get the same facts from IntelliSense, agents from `$help`); nothing in
   this epic depends on the answer.

8. **`guides.search` is text search and says so.** It sits beside `helpSearch`, which walks the
   descriptor graph (`src/shared/ai-vision/help-search.ts`). Two different questions — "what does
   the documentation say about X" versus "where in the object model is X" — and the root overview
   and both `$help` texts must say which is which, or agents will pick one at random.

9. **The QA gate needs a question set that does not exist yet.** `qa/surfaces/gate.md` has exactly
   one documentation scenario (G.10, which tests answering *without* a guide tool). This epic
   authors a small guide-question set — user-phrased "how do I …" and "where is …" questions whose
   answers live in the corpus — as part of the gate task, and logs the run to `qa/runs/`. The set
   becomes the reusable gate for EPIC-094 and EPIC-095.

## Scope

**In scope.** The corpus move; front matter; `src/shared/guides/`; the main-process `guides` node
(`guides`, `guides.<folder>`, `guides.<folder>.<page>`, `guides["folder/page"]`, `guides.<page>.layout`,
`guides.search(query, limit = 10)`, `guides.whatsNew`); resource re-pointing; `SERVER_INSTRUCTIONS`,
overview and node-help pointers; `electron-builder.yml` confirmation; the in-repo pointers that break
now; the QA gate and live verification.

**Out of scope** — and each has an epic that owns it:

- Rewriting, merging or splitting any page's prose, `docs/editors.md` above all (EPIC-094).
- Writing `## Layout` schemas. `guides.<page>.layout` ships in this epic and returns the `## Layout`
  section when a page has one — no page has one yet, so it returns a clear message saying so. The
  path exists first so EPIC-094 only writes markdown (EPIC-094).
- The About page, the guide browser, the guide link scheme, `F1`, the Menu Bar item, the
  `about-view` facade (EPIC-093).
- Deleting `docs/`, rewriting `/userdoc` and `/document` wholesale, `CONTRIBUTING.md` (EPIC-095).
  Only the minimum re-pointing needed to keep `/userdoc` and the release process working is done
  here.
- Mneme indexing of the corpus. Recorded in the roadmap as a possible later enhancement; guide
  search must work without it.

## Risks and abort criteria

- **The move diff is unreviewable if anything else rides along.** A single reworded sentence hides
  in 11k lines of `git mv`. Mitigation: `git log --follow` plus `git diff -M` must show every moved
  file as a pure rename except for the front-matter block and the deleted breadcrumb line; the
  review checks that mechanically, not by reading prose.
- **Resource URIs are a published contract.** A client may have pinned `persephone://guides/notebook`.
  The URIs, resource `name`s and `description`s must come out of this epic byte-identical; only the
  `file` they resolve to changes. Verified live, not by inspection.
- **`readGuideFile` takes a bare filename today** and resolves it through `getAssetPath`. The tree
  introduces subdirectories, so the loader takes a relative path — and must refuse to escape
  `assets/guides/` (`..`, absolute paths, drive letters) since page paths now arrive from an agent
  argument. This is the one genuine security surface in the epic.
- **Search quality is the whole value of the node.** `guides.search("filter rows")` returning
  nothing useful makes the corpus unreachable in practice, and no build or typecheck catches it.
  US-1364 verifies it live against real queries.
- **Abort criterion:** if the QA gate fails after two rounds of documentation/hint fixes, the node
  ships but the epic does not close, and the failure is recorded on the roadmap row rather than
  papered over. Retiring nothing until its replacement passes the same gate is roadmap principle 5,
  and EPIC-095 depends on this gate having actually passed.

## Needs user check

Recorded rather than blocking; work proceeds on the defaults.

1. **Root name.** Shipping as `guides` (decision 1). If `userGuide` is preferred, it is a rename in
   the main root descriptor, `RESERVED_ROOT_NAMES` and the overview line — small, and cheapest
   before EPIC-093 wires the About page to it.
2. **The API reference's long-term fate** (decision 7). Moved unchanged; the keep-or-drop decision
   is deferred to after EPIC-095, with usage evidence if the About page counts guide opens.
3. **`docs/` stubs versus a hard cut.** Stubs are shipped so nothing 404s before EPIC-095. If the
   user would rather `docs/` disappear now, EPIC-095's deletion step can be pulled forward.
4. **Front matter on GitHub.** A `---` block renders as a table or as literal text depending on the
   viewer. Judged acceptable (decision 2) because the in-app copy is canonical, but the user may
   dislike how it looks in the GitHub preview of `assets/guides/index.md`.
