# EPIC-185: UI test coverage, phase 4b — viewer editors

## Status

**Status:** Completed 2026-11-17
**Created:** 2026-11-17

## Overview

Second half of Phase 4 of the [UI test coverage roadmap](../reviews/ui-test-roadmap.md), after
[EPIC-184](EPIC-184.md) (phase 4a). This epic covers the viewer editors: HTML Preview, SVG Preview, Image Viewer,
Log View, the Link editor, the Environment Variables editor and the Video Player. The tests go under
`integration-test/tests/editors/`. The deliverable is the tests plus the bugs they find. The runner needs no new
features.

## Goals

- Each editor module below has tests for every behavior on its checklist that `call` can reach. Whatever `call`
  cannot reach is listed as uncovered, with the reason.
- Claude fixes each app bug the tests find and adds a `whats-new.md` line for it.
- Stale guide text found along the way is fixed.

## Non-goals

- Grid, Settings, Tools hub and the other Phase 5 editors.
- Anything that needs the network, VLC, or a board's `image.edit` capability beyond checking the message the guide
  documents when it is missing. "Open in Drawing" is covered only if the bundled Excalidraw board opens in the test
  profile without network access.
- Torrent and recording sources in the Video Player.

## Working model

Same as [EPIC-184](EPIC-184.md#working-model):

- **Codex (Luna) writes, runs and triages** each task's tests. This epic's checklist is the plan, so there is no
  separate task document. Codex reads the editor's guide (`assets/guides/editors/<name>.md`) and source and explores
  the call tree against an `npm run test:ui -- --open` instance that Claude starts. It runs the tests with
  `npm run test:ui -- --attach --area editors/<module>`. It never uses the user's own Persephone (MCP port 7865).
- **App bugs:** Codex never fixes them and never bends a test to pass. It leaves the test failing and reports steps,
  expected, actual and the failing test in the task's Results block. Claude investigates and fixes every one.
- **Claude per task:** reads the new tests and checks for real assertions, no fixed sleeps, and nothing that passes
  without checking. Sends corrections to the same Codex session, fixes the reported bugs, and reruns the tests.
- **Claude per epic:** runs the whole `editors` area twice in launched mode, then the full suite once, and fixes
  anything still failing.
- Every test works only inside its own folder under `ctx.fixture(...)`. Shared helpers go to
  `integration-test/tests/editors/helpers.mjs` (area-only, per `integration-tests.md`).
- Binary fixtures (images, audio) are generated by the test inside its fixture folder, not committed, unless a tiny
  committed file is the only way. No external tools (ffmpeg and the like) are assumed.

## Area checklists

### US-2048: HTML and SVG preview — `tests/editors/html/`, `tests/editors/svg/`

- An HTML file opens in Preview and renders its markup; script in the page runs; a source edit shows up in the preview.
- A plain local HTML file loads a relative stylesheet or image from its own folder.
- **Show Resources** produces a link collection with the page's resources.
- HTML capture: **Save** writes an image file, **Copy** completes (as far as `call` observes it).
- An SVG file opens in SVG Preview, reflects unsaved source edits, and zoom works as far as the facade exposes it.
- SVG **Save as PNG** writes a valid PNG; **Copy** completes.
- Without an `image.edit` provider (if the test profile has none), **Open in Drawing** shows the documented message;
  otherwise it opens the drawing page.

  - `HTML Preview runs scripts and reflects source edits`
  - `plain local HTML loads a relative image resource`
  - `Show Resources opens a collection containing page resources`
  - `HTML capture saves a PNG and copy completes`
- Tests added in [`svg.test.mjs`](../../integration-test/tests/editors/svg/svg.test.mjs):
  - `SVG Preview zooms in and resets to fit`
  - `SVG Preview renders unsaved source edits`
  - `SVG PNG export writes a valid image and copy completes`
  - `Open in Drawing follows the available image editor`
- `npm run test:ui -- --attach --area editors/html`: **4 passed, 0 failed, 0 skipped** (twice).
- `npm run test:ui -- --attach --area editors/svg`: **4 passed, 0 failed, 0 skipped** (twice).

The save menu options are observed and PNG export to a fixture path is verified, but selecting a path in the native Save Image dialog is outside the `call` element surface (the guide lists native save dialog controls as having no `elements` entry), so byte-for-byte Save original output cannot be observed.

### US-2051: Link editor — `tests/editors/links/`

- A `.link.json` fixture opens in the Link editor; the facade's link, category and tag snapshots match the file.
- Add, edit and delete a link through the facade's mutation methods; the change is saved to the file.
- Filter by category, tag and hostname, as far as `call` reaches the sidebar panels.
- List and tile views switch, and the choice is remembered per collection as the guide says.
- JSON with `"type": "link-editor"` and `"links"` offers the Links switch.

#### Results

- Tests added in [`links.test.mjs`](../../integration-test/tests/editors/links/links.test.mjs):
  - `Link editor opens a collection and exposes link, category, and tag snapshots`
  - `Link editor facade mutations update snapshots and save the collection`
  - `Link editor filters the visible collection through sidebar panels`
  - `Link editor list and tile choices are remembered for collection filters`
  - `JSON with the link-editor marker offers the Links switch`
- `npm run test:ui -- --attach --area editors/links`: **5 passed, 0 failed, 0 skipped** (twice).
- App bugs found: **1**. Steps: open a `.link.json` collection, choose **Landscape** for the `Reference` category,
  switch to `Reading` and choose **List**, then return to `Reference` and confirm **Landscape** is still selected.
  Close and reopen the same file and select `Reference`. Expected: the collection remembers **Landscape** for that
  category. Actual: the toolbar shows **List** after reopening, and the saved JSON has no `state.categoryViewMode`.
  Failing test: `Link editor list and tile choices are remembered for collection filters` in `links.test.mjs`.
- Uncovered: **none**. The Link facade, category/tag/hostname panels, view controls and editor switch are reachable
  through `call` and were exercised.
- Claude check (2026-11-17): **app bug fixed, cause differs from the report.** The view choice was saved
  correctly; the test lost it in a race. The Link editor writes changes to its page 300 ms after the last one. The
  page's `modified` ignored that pending write, so a close right after a change skipped the save prompt. A switch to
  Text Editor handed the host over before the old editor flushed, so the change was dropped. `LinkEditor` now counts
  the pending write in `modified`, flushes it before the release prompt, and flushes it while the host is handed over.
  The mutation test now proves a save on disk, and the view-mode snapshot reads wait. `--attach --area editors/links`:
  **5 passed**, twice.

## Concerns

1. **Binary fixtures.** No ffmpeg on this machine. PNG and WAV are easy to generate in a test; HLS segments are
   not, so HLS may stay uncovered.
2. **The fixture server serves `text/plain`.** Viewers that check the content type may refuse fixture URLs. If one
   does, that is a runner limit, not an app bug; it is listed as uncovered rather than worked around in the runner.
3. **Shared stores.** The env-vars store and the managed Log View page are profile-wide. Tests clean up what they add
   so module order does not matter.
4. **Rendering is asynchronous.** Previews and media load after a delay. Tests wait with `ctx.waitFor`, never with a
   fixed sleep.
