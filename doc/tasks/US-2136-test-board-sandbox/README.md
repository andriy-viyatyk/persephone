# US-2136: Test mode: environment sandbox for board processes, then cover Agent Chat offline states

Epic: [EPIC-201: Board data and network isolation](../../epics/EPIC-201.md)

## Goal

In an owned test instance, give every board service and board-started process isolated Windows profile folders and a system-only `PATH`, while keeping the host app's existing environment behavior intact. The existing test-instance `LOCALAPPDATA` redirect remains global; the new `USERPROFILE`, `APPDATA`, CLI-config, and `PATH` redirects apply to board processes only. Add the Persephone-side integration coverage and coordinate Agent Chat's offline behavior fix in a separate run in the boards repository.

## Background

- EPIC-201 Decision 5 settles the test-only redirects for board processes: `USERPROFILE`, `HOMEDRIVE`/`HOMEPATH`, `APPDATA`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, and `PATH`. The existing EPIC-197 global test-instance `LOCALAPPDATA` redirect remains unchanged; the board sandbox sets that variable to the same `<userData>/test-local-app-data` value. The host and app-level processes retain their existing environment behavior, including that pre-existing LOCALAPPDATA redirect.
- US-2132 is implemented. `src/main/board-process-environment.ts::boardProcessEnvironment(base: NodeJS.ProcessEnv, boardRoot: string)` copies the supplied base, adds the selected `PERSEPHONE_BOARD_DATA`, and returns the result. `src/main/module-service/process.ts::ModuleServiceProcess.buildServiceEnvironment()` supplies its current allowlist to that helper. Board `execute` and `executeNode` flow through `src/main/board-host/rpc/events.ts` into `src/main/command-runner.ts`; board callers pass `boardRoot`, and the runner supplies `{ ...process.env, ...(opts?.env ?? {}) }` (plus `NODE_NO_WARNINGS` for executeNode) as the base. Extend the existing helper by applying the test sandbox as its final transformation; do not redesign these callers, add an `extraEnv` parameter, or replace their current environment composition.
- US-2132 added `{ op: "environment" }` to `integration-test/fixtures/boards/module-service/round-trip-board/scripts/service.mjs`, returning `boardData`, and added a test in `integration-test/tests/capabilities/module-service/module-service.test.mjs` for that value. Extend the same operation with the selected environment values and leave the existing US-2132 test unchanged. Add a separate test for the redirects and board child-process paths. The current LOCALAPPDATA guard remains `integration-test/tests/boards/bridge/service-environment.test.mjs`, using `integration-test/fixtures/boards/bridge/service-environment-board/scripts/service.mjs`.
- No renderer bridge API change is needed for environment inheritance. Do not change `window.persephone`, add protocol messages, or bump `BOARD_BRIDGE_VERSION` for this work.

## Concerns
