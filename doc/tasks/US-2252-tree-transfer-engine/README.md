# US-2252: Transfer engine (`TreeTransfer`)

## Goal

Provide one cross-tree copy/move collaborator for EPIC-218, with bounded byte transfer, conflict decisions, progress, cancellation and per-item outcomes. Leave UI integration to US-2253–US-2255.

## Background

[EPIC-218](../../epics/EPIC-218.md) and [remote trees roadmap phase 2](../../reviews/remote-trees-roadmap.md) retain local-to-local `copyPathsInto` and same-tree move `rename`; they require no rollback, file-link content copying, folder-link skipping, and target-name errors. [US-2251](../US-2251-chunked-provider-writes/README.md) is implemented before this task and provides `IProvider.beginWrite` / `IProviderWrite`.

`ITreeProvider` (`src/renderer/api/types/io.tree.d.ts`) exposes `list(path)`, `stat(path)`, `resolveLink(path)`, optional `mkdir` and `deleteItem`; `ILink.href` identifies an item, while `ITreeStat` has no link-kind information. `createTreeProvider` uses `{ type, rootPath, url?, config? }`; board `sourceUrl` identity uses `boardTreeSourceIdentity` with type, config and rootPath. `copyPathsInto` reports `{ copied, errors }`, counts files for progress and removes a source after its complete copy.

`FileTreeProvider.list` catches listing errors and inserts a synthetic `..` row; its `stat` follows symlinks and does not identify them. `ProxyTreeProvider.list` maps board hrefs to provider paths privately and can return truncated results; `resolveLink` requires a previously mapped path. These existing interfaces cannot safely support complete recursive moves or construct a new board destination href by themselves. `ContentPipe.createReadStream` delegates only for an untransformed provider with a stream; otherwise it buffers the entire pipe. `ProxyProvider` exposes bounded range streams only when the board implements `readRange`; `FileProvider` always exposes a stream. For non-streaming boards, `src/module-service-host/provider-dispatch.ts` rejects `readBinary` results over the cap before copying them to the renderer; the board implementation has already allocated its result at that point. `MAX_BOARD_PIPE_CHUNK_BYTES` is 1 MiB and `MAX_BUFFERED_PIPE_BYTES` is 256 MiB in `src/shared/board-pipe-constants.ts`.

`pipeFromLink` in `src/renderer/content/rebuild-pipe.ts` resolves a raw link without opening a page, including registered schemes and file/archive descriptors. Board `treeList` responses carry an explicit `truncated` flag and each item has both `path` and `href` (`src/ipc/module-service-channels.ts`); `ProxyTreeProvider` currently discards completeness and exposes neither mapping. Board `treeStat` has neither link kind nor an href for a missing path. `src/module-service-host/tree-provider-dispatch.ts` validates and copies those fields, so extending the existing result requires changing that validation as well. Board paths are validated by `src/shared/board/board-tree-path.ts`. `FileTreeProvider.deleteItem` recursively removes directories. `ProxyTreeProvider.deleteItem` forwards `treeDelete` to the board, whose `delete(config, path)` implementation owns its semantics; `assets/guides/boards/content-providers.md` does not specify recursion. The fixture `integration-test/fixtures/boards/trees/tree-board/scripts/service.mjs` rejects deletion of nonempty directories.

## Implementation Plan

- [ ] **Scope and ownership.** `src/renderer/content/tree-providers/TreeTransfer.ts` owns orchestration and transfer policy; it accepts file and board (`ProxyTreeProvider`) trees with the capabilities below. Archive is excluded even as a source for this task: its transformer buffers whole entries, its listing swallows errors, and it lacks reliable link metadata. Mneme and link collections are also excluded: their addressing and completeness semantics have not been established for this contract. Reject unsupported trees explicitly, never fall back to an unsafe recursive move. This narrows the epic's generic “any two trees” to local and board for this task; adding other kinds needs a separate, verified adapter. Preserve `copyPathsInto` for any local-to-local pair and `rename` for a same-tree move; callers choose these before constructing `TreeTransfer`. For a same-tree board copy, callers may pass the same live provider as both source and target with `move: false`; the existing containment guard still rejects a folder copied into itself or its subtree.

- [ ] **Transfer capability, not tree-type branches at callers.** Add an optional transfer capability in `src/renderer/content/tree-providers/tree-provider-capabilities.ts`, implemented by `FileTreeProvider.ts` and `ProxyTreeProvider.ts`. It owns path/address translation, strict listing, link classification, target names, deletion strategy and backing-store identity. Define operations that: convert a listed `ILink` to its provider path and verify it; join a validated child name to a folder path; list immediate children completely or throw; stat without hiding errors with `kind: file | directory | file-symlink | directory-symlink` and size where known; resolve a content href for an existing source **and a not-yet-created destination**; compare backing store and containment; and expose whether directory deletion is recursive or requires an empty folder. For move, unknown deletion semantics fail closed. Missing/unknown kind, incomplete listing, unknown writable target link, or missing required capability fails the item before deletion. Do not infer board paths from hrefs or fabricate board scheme URLs. Expose a stable backing-store key for board type + config **excluding rootPath**, reusing `stableJson` in `tree-provider-identity.ts`; existing `boardTreeSourceIdentity` includes rootPath and is insufficient for overlapping roots. For local paths reuse `fpNormalizeForCompare`, `fpJoin` and `isKeyInside` from `src/renderer/core/utils/file-path.ts` and `src/shared/path-containment.ts`. Reject any folder target inside itself on the same backing store, even when tree roots differ; if containment cannot be proved safe, fail closed.

- [ ] **Local correctness.** In `FileTreeProvider.ts`, reuse `listStrict` (exclude the private synthetic parent row), Node `lstat` and followed `stat` in this existing low-level filesystem exception. Classify links before recursion, report broken links as failures, and treat a directory symlink as skipped; file symlinks read their target bytes. A skipped descendant makes its selected ancestor incomplete for move, so it is retained. Preserve strict errors; do not use the current `list` or `stat` catch-and-return fallback for transfer. Validate each target component before joining: reject separators, NUL, `.` and `..`; on Windows also reject reserved device names, control characters, `<>:"/\\|?*`, and trailing spaces/dots. Let target filesystem errors and case-insensitive collisions surface per item; never silently rewrite names. `src/shared/platform.ts` already provides `isWindows`.

- [ ] **Board capability.** In `ProxyTreeProvider.ts`, reuse its accepted-provider checks, cached href/path mapping and `isValidBoardTreePath`; add a strict listing route that propagates failures and refuses `truncated: true`, retaining the mapping for each returned child. Extend existing `treeStat` response in `src/ipc/module-service-channels.ts` with optional `linkKind`, target `href` (including for a nonexistent child), and directory `deleteMode: "recursive" | "empty-only"`, and validate/copy these in `src/module-service-host/tree-provider-dispatch.ts` and `src/renderer/api/module-service.ts`. The board implementation returns `linkKind` for every existing node, reports `deleteMode` for directories that can be deleted, and can return a content href for a requested child even when it does not exist. The fixture reports `empty-only`; missing delete mode makes a directory move unsupported without affecting copy or existing browsing. Require both capabilities for the relevant transfer operation; absent metadata is an explicit unsupported failure, preserving existing boards' browsing behavior. Verify returned href with the same ownership/scheme and credential checks used by list; preserve opaque config and never construct it from URL spelling. Extend existing `treeProviders.register` stat contract and fixture `integration-test/fixtures/boards/trees/tree-board/scripts/service.mjs` accordingly; the existing provider channel and `treeStat` operation carry the extra data, with no new protocol, correlator or message envelope. Board-specific validation stays in `src/shared/board/` and board registries or the existing dispatch validation boundary. US-2251 bumps `BOARD_BRIDGE_VERSION` in `src/shared/board-bridge-version.ts` to `1.66.0` before this task. Both ship in the same unreleased version: extend the existing `1.66.0` history line in `assets/guides/agents/boards/bridge-versions.md` for these service API changes, with no additional bump; keep the fixture manifest `minBridgeVersion` at `1.66.0`. US-2257 documents the tree stat and deletion contract in `assets/guides/boards/content-providers.md`.

- [ ] **Caller API.** Export the following shape from `TreeTransfer.ts`. A caller passes live providers and selected links; it owns provider lifecycle, including disposing a provider it creates via `createTreeProvider`. The engine converts each source link through its provider capability; it never treats `ILink.href` as a board path. Target `folderPath` is the provider's category/list path (root is `provider.rootPath`). A re-created proxy must list each selected item's parent first to rebuild the validated href-to-path map. Source and target can be the same live provider for a same-tree board copy; `sourceUrl` alone is not sufficient to detect overlapping roots. OS-path callers construct a file provider with the relevant root and obtain links by listing its parent. Example:

  ```ts
  // Before: no cross-tree collaborator; local callers use copyPathsInto(paths, dir, { move }).
  // After: callers already holding a provider and its selected ILinks:
  const results = await new TreeTransfer().transfer(
      { provider: sourceProvider, items: selectedLinks },
      { provider: targetProvider, folderPath: targetCategory },
      { move, signal, onConflict, onProgress },
  );
  ```

  Define `onConflict({ source, destinationPath, sourceKind, destinationKind })` returning `{ action: "overwrite" | "skip" | "keep-both", applyToAll: boolean }`; engine remembers apply-to-all for the batch, but revalidates kind compatibility. Overwrite merges directory with directory and prompts separately for nested conflicts; overwrite file replaces file; file/directory mismatches fail explicitly. Keep-both uses `name (1).ext`, `name (2).ext`, preserving the last extension for files, validates and probes target `stat` until unused, and handles races as failures. Skip includes the whole selected conflict subtree and makes any selected ancestor incomplete for move.

- [ ] **Walk and outcome.** Preflight and enumerate with strict list and stat, detect duplicate/overlapping selections (retain the outer selection, report redundant selection as skipped), avoid parent navigation rows and reject invalid components. Check target `writable` and `mkdir` for folders, then create each missing destination directory with `targetProvider.mkdir(path)` before visiting its children; do not require mkdir for file-only transfers. Track each selected top-level item independently. First copy *all* selections, then, only if not cancelled, delete each completely copied selected subtree using its provider's declared deletion strategy: call `deleteItem` once on the selected item when deletion is recursive (including `FileTreeProvider`), or delete bottom-up using each original listed href only when the provider requires empty folders; a failure, skipped link or conflict, truncation, or failed child prevents deletion of its entire selected ancestor. A delete failure stops deletion of that subtree and reports copied-but-not-deleted, including paths already deleted; deletion itself cannot be rolled back. Return one result per input with `source`, optional `destinationPath`, `status: copied | moved | skipped | failed | cancelled | copied-not-deleted` and nested failures/messages; include aggregate `copied` file count and `errors` analogous to `CopyPathsResult`. A cancellation marks remaining items cancelled and never starts deletion after cancellation; a delete already in flight cannot be reversed. No rollback of completed files or folders.

- [ ] **Content and bounded memory.** Resolve source `pipeFromLink(sourceProvider.resolveLink(sourcePath))` and target `pipeFromLink(targetCapability.resolveContentHref(destinationPath))`, in `src/renderer/content/rebuild-pipe.ts`; dispose both in `finally`. Never write directly to an underlying provider through a transformed pipe: chunked destination requires no transformers; otherwise use the full pipe's buffered write only when demonstrably bounded. Require a safe known size before any buffered read, and fail clearly if absent or above `MAX_BUFFERED_PIPE_BYTES`. A transformer can expand data and `ContentPipe.stat()` itself buffers: until a bounded transformed reader exists, reject transformed sources rather than claim the cap can be enforced. For an untransformed source with `provider.createReadStream`, read inclusive ranges up to `MAX_BOARD_PIPE_CHUNK_BYTES` and feed chunks sequentially with backpressure. Verify each range length, advance by actual bytes, fail on premature EOF or excess, and handle zero-length files. Use `pipe.stat({ signal })` only on untransformed providers with safe integer sizes; reject unknown sizes. When target only offers buffered `writeBinary`, accumulate no more than the cap and check the final length; when source lacks stream, use `pipe.readBinary({ signal })` only with a known capped size, verify returned size and cap. For a non-streaming board, the existing utility-process `readBinary` result limit rejects oversized data before copying it to the renderer; it cannot prevent the board implementation itself from allocating an oversized result. A local `FileProvider` always has a read stream. Detect size changes and short reads; same-size concurrent changes cannot be detected by this interface and require provider snapshots or conditional operations to prevent.

- [ ] **US-2251 integration contract.** The prerequisite [US-2251 plan](../US-2251-chunked-provider-writes/README.md) specifies `IProvider.beginWrite({ signal })` returning an `IProviderWrite` with `write(chunk)`, `commit()`, and idempotent `abort()`. It exposes an optional chunk session for an untransformed target: begin on the destination, sequential bounded writes, commit, and idempotent abort; begin/write/commit accept cancellation or provide equivalent cancellation, and abort must be callable after the transfer signal is aborted. Commit atomically replaces the destination; abort or failure cleans the temporary file without damaging an existing destination. Absence means buffered `IContentPipe.writeBinary` up to the cap. Writes must create missing files. The engine checks signal before each operation, passes it to reads, destroys in-flight streams on abort, aborts any uncommitted session in `finally`, and reports cleanup failure without hiding the original error. `writeBinary` currently has no signal or atomicity guarantee: once it starts, await its outcome, report cancellation honestly and do not delete sources; a cancelled buffered write may leave a file. Tree list/stat/mkdir/delete currently do not accept the caller signal: check between operations; do not promise interruption of an in-flight tree operation.

- [ ] **Progress.** Report `{ filesDone, filesTotal?, bytesDone, bytesTotal?, currentName }`, analogous to `copyPathsInto`'s file-count callback. Increment bytes only after a successful chunk/write and files only after commit/write completes; totals are optional until the strict walk and trustworthy sizes establish them. Unknown totals stay undefined, never guessed. Continue independent source items after an ordinary failure; on abort stop scheduling new work. Surface per-item errors using `errMessage` from `src/shared/utils.ts`.

- [ ] **Validation.** Run `npm run typecheck` and `npm run lint` for implementation, and exercise the transfer through the US-2256 UI suite. US-2256 must cover local↔board and board↔board copies/moves, overlapping roots/subtree refusal, file and folder symlinks, bad and case-colliding names, nested conflict choices and apply-to-all, truncation and listing/stat failure, missing link metadata, deletion mode and destination href, recursive and empty-only deletion, read/write failures and delete failures, empty/large/multi-chunk files, unknown and oversized buffered input, cancellation during read/write and cleanup, and retention of partially copied move sources. No unit tests are planned.

## Concerns / Open questions

- Board services must provide trustworthy link-kind and destination-href metadata, and identify their backing store consistently across overlapping roots. Old boards continue browsing but cannot participate in transfers requiring missing metadata. Paths and content can change between preflight and use; without provider-side conditional writes or snapshots, races cannot be fully eliminated. Report failures and never claim rollback.
- The target's actual OS and case rules are board-owned: core validates local Windows names; a remote board must reject invalid names and collisions in its write/mkdir operations. Do not apply local OS rules to remote names.
- No `window.persephone` UI surface or new protocol is added by the engine. The existing board service stat contract is bridge surface and requires the version/history update above. No `await import()` or import-zone bypass; no roadmap §2.3 god file growth. Any strict-folder null-check fix is type-only unless separately recorded as a behavioral change.

## Acceptance Criteria

- File↔board and board↔board transfers use the engine; unsupported providers fail clearly; local↔local and same-tree moves retain their existing paths.
- Strict complete traversal, link handling, invalid names, collision choices and containment follow the rules above. No source is deleted unless its entire selected subtree copied successfully, and deletion waits until all copying ends.
- Progress and per-item results distinguish skipped, failed, cancelled and copied-but-not-deleted items. Cancellation aborts active supported reads and chunk sessions; completed work remains.
- Chunked copies stay bounded; buffered fallback enforces the cap and reports unsupported or oversized content clearly. Incomplete chunk sessions leave no half file.
- Provider bridge changes reuse existing operations and validation, have the bridge history entry, and meet lint/typecheck; US-2256 covers the scenarios listed above.
