# US-2245: ProxyTreeProvider

## Goal

Implement the board-backed `ITreeProvider` for [EPIC-217](../../epics/EPIC-217.md), using the reviewed [US-2243 factory](../US-2243-tree-provider-factory/README.md) and [US-2244 service API](../US-2244-board-tree-service-api/README.md) as contracts.

**Out of scope:** Board service protocol, Explorer persistence and the test board.

## Background

- US-2243 specifies exact factory registrations followed by ordered matchers; its source may be changing. US-2244 specifies `tree: true`, accepted declarations and schemes, `moduleService.requestTree`, validated tree results and per-type lease capabilities. Its implementation is a prerequisite. The service returns `{ items, truncated }`; items contain `name`, absolute board `path`, claimed-scheme `href`, `isDirectory`, `size?`, `mtime?`. Host validation owns shape, 5,000-item bound, direct-child paths and uniqueness. Config is opaque board-owned data (epic decision 5); core does not parse connection settings or construct hrefs from them.
- `src/renderer/content/registry.ts:166–203,222,304–325,383–402,442–447` owns provider registrations, declarations and availability. `MissingProvider` is returned immediately, waits for declarations, throws `MissingProviderError` for absent/untrusted declarations and `ProviderUnavailableError` for a trusted declaration without a registered provider, and retries failed resolution. Declarations and accepted registrations are separate: `src/renderer/api/boards/custom-editor-registry.ts:239–289,487–504` collects declarations then attempts ownership and scheme registration. Current registry has no accepted-owner accessor; a declaration alone is not evidence of a successful claim. Refresh signals availability before claims are rebuilt, so a listener must schedule a retry after the synchronous refresh completes.
- `src/renderer/content/scheme-registry.ts:50–53,124–134` owns `schemeOf` and `boardSchemeOwner`. Both accepted ownership and the accepted declaration's per-type scheme list are necessary: one board can own several types. They are not sufficient when two types from the same board declare the same scheme: only the first scheme registration succeeds, and its hook is bound to that first type. `custom-editor-registry.ts:157–190,273–278` installs hooks binding each accepted scheme to its provider type; parse sets `data.url`, resolve builds `{ type, config: { url } }`, then `createPipeFromDescriptor` reaches `createBoardProvider` (`src/renderer/content/board-provider-factory.ts:4–10`) and `ProxyProvider`. `src/renderer/content/parsers.ts` and `resolvers.ts` dispatch these registered hooks.
- `src/renderer/api/types/io.tree.d.ts:12–117,126–162,200–209` defines the interface and `ILink`. `FileTreeProvider.ts:97–155`, `MnemeTreeProvider.ts:60–88`, and `ArchiveTreeProvider.ts:40–87` put the directory path in `category`, use empty folder tags and lowercase extension tags for files, and sort folders before files. Archive/file may set image previews; board hrefs need no image preview. The icon renderer consumes `icon: "board", boardIconRoot` (`src/renderer/components/icons/icon-elements.ts:111`); `BoardEditorModel.ts:313` uses the same board glyph mechanism, without content importing components.
- Root listing uses `provider.rootPath` (`src/renderer/components/tree-provider/provider-tree-store.ts:112–135`); node identity, saved expansion and lookup use `item.href` (`tree-provider-node.ts:22–35`, `provider-tree-expansion.ts:25–31,64–80,128–133`). Nested `list` and rename receive `category + "/" + title` (`TreeProviderViewModel.ts:462–481`, `provider-tree-store.ts:199–209`); Category view reconstructs it too (`CategoryViewModel.ts:623–625`). That join yields `//name` at `/`. Delete receives href (`item-crud-actions.ts:94–109`). The board's path and href cannot be assumed interchangeable. `CategoryEditorModel.ts:62–72,168` locates a host by exact type and `sourceUrl`.
- Menus read `provider.writable` and each optional function when built (`item-menus.ts:52–68,213`, `plural-actions.ts:87,117–149`); Category view also checks dynamically (`CategoryView.ts:343–344`, `CategoryViewModel.ts:395`). `item-crud-actions.ts:51–109` checks the actual method at execution. A single `writable` flag does not express individual methods.
- `CategoryViewModel.ts:251–275` / `CategoryView.ts:220–228` display pending and errors. Tree `TreeProviderViewModel.ts:341–383` displays root errors via `errMessage`, but has no loading state; `provider-tree-store.ts:206–235` currently turns lazy-list failures into empty children. `ProxyProvider.ts:66–90,144–165` maps wire failures to `ProviderOperationError` and transport failures to `ProviderUnavailableError` with cause.

## Implementation Plan

- [ ] **Factory and gate:** in `src/renderer/content/tree-providers/tree-provider-factory.ts`, register exactly one ordered matcher for namespaced types, using `boardProviderTypeRefusal` from `src/renderer/content/registry.ts`; exact built-ins still win. The matcher must be able to select an absent board type so restoration can succeed: it constructs a proxy shell for a namespaced descriptor, not an authorized service delegate. Unknown non-namespaced types retain factory failure. Before every request, after `whenProviderDeclarationsReady`, resolve the current declaration and accepted registration; require trusted declaration, `tree === true`, board root and accepted board owner matching that root. Add a narrowly scoped accepted-board-owner query to `registry.ts` backed by `providerOwnership` if US-2244 has not added one; keep ownership rules there, do not duplicate trust, manifest or root normalization policy. Never dispatch to a rejected or untrusted owner. Missing/untrusted declaration throws existing `MissingProviderError`; declaration with no tree flag or no matching accepted registration throws `ProviderUnavailableError`. Do not cache failed authorization or a stale owner. A shell is deliberate: US-2246 can retain the host, display **Provider missing** using `isProviderResolutionError`, subscribe to `subscribeProviderAvailability`, schedule a retry after the refresh, and rebuild when ownership returns; it must unsubscribe on disposal. A factory throw would prevent this retained recovery. An accepted tree declaration is required to activate the proxy, not to allocate its inert shell.
- [ ] **Descriptor/identity:** implement `src/renderer/content/tree-providers/ProxyTreeProvider.ts`, storing `{ type, config, rootPath }` and sending config unchanged. Set `sourceUrl` to `"board-tree:" + stableJson([type, config ?? null, rootPath])`, recursively sorting object keys while preserving array order and primitive values. Config comes from persisted JSON and remains opaque; omitted and null config have the same identity. Do not log config or store credentials in it. `displayName` is the accepted declaration's `boardName` or type, optionally combined with root path; `rootPath` is the descriptor's exact board path. Validate root under US-2244's absolute-path contract, preserving `/`; reject noncanonical trailing separators except `/`. Do not derive connection data from config or use US-2243's `url` as a substitute.
- [ ] **Listing and ownership:** before dispatch, resolve the accepted owner as in the gate; forward `treeList` with the original config and requested board path. Validate the response envelope and operation per US-2244. Before returning any item, require `schemeOf(item.href)` to be in the accepted declaration's normalized schemes for this type and `boardSchemeOwner(scheme)` to equal that board's root. On any failure reject the entire list with `ProviderOperationError("provider-invalid-result", ...)`. Reuse host validation rather than repeat its bounds and item-shape rules. Map each wire item to `{ title: name, href, category: requestedPath, tags: isDirectory ? [] : extensionTags, isDirectory, size, mtime }`, with `fpExtname(name).toLowerCase()` as in Mneme, no `imgSrc`; sort folders then files as existing providers do. Rely on the host's direct-child guarantee: the root-safe joined category and title equal the returned `path`. Maintain a simple per-instance `Map<hrefKey, path>` and a reverse path-to-href map as needed for navigation and `resolveLink`; fill them from each successful list, overwriting entries for re-listed folders, and clear them on dispose. Do not parse an opaque board href; unknown href or path produces a clear error.
- [ ] **Path join:** extract a focused provider-tree path helper in `src/renderer/components/tree-provider/` and use it from `TreeProviderViewModel.ts`, `CategoryViewModel.ts`, and `item-crud-actions.ts` for child list, create-folder and rename paths. It must preserve existing path semantics while joining `/` and `name` as `/name`, not `//name`; handle a non-root category without adding a second separator. Move the existing tree-model path reconstruction into the helper so roadmap §2.3's `TreeProviderViewModel.ts` does not grow. For example:

  ```ts
  // Before → after, root category:
  category + "/" + item.title  // "/" + "/" + "docs" = "//docs"
  joinTreeChild(category, item.title) // "/docs"
  ```

- [ ] **Navigation and stat:** `stat(path)` forwards `treeStat` and returns its `ITreeStat` fields, preserving `{ exists: false, isDirectory: false }`. For a cached path, `resolveLink(path)` returns its exact board href; for an unknown path throw a clear error rather than synthesize a URL. No `addItem` is exposed, so the New File call site does not require resolving a nonexistent child. `getNavigationUrl(item)` returns file `item.href`, and for a directory uses `encodeCategoryLink({ type, url: sourceUrl, category: boardPath })`; recognize the synthetic root by `rootPath`, otherwise derive the path from `category` and title with the same root-safe join and verify the cached mapping. `getNavigationUrlByHref` looks up exact href to path, calls `stat(path)`, returns the href for a file or encoded category for a directory; accept `rootPath` as root and fail clearly on an unknown href, never reinterpret a claimed URL as a board path. Build `getCategorySegments` as root-relative breadcrumbs retaining absolute category paths, excluding the root; handle `/` and nested roots. `describeRoot` returns `{ icon: "board", boardIconRoot: acceptedRoot }` when authorized, otherwise `{}`; reuse the existing icon renderer, not a components import.
- [ ] **Unicode category links:** fix `src/renderer/content/tree-providers/tree-provider-link.ts:30`: `btoa(JSON.stringify(link))` fails for non-Latin paths, including existing local folders. Encode UTF-8 with an explicit version prefix and decode both the new form and existing unprefixed links, preserving stored links.
- [ ] **Truncation:** when a successful list reports `truncated: true`, `ProxyTreeProvider` calls `ui.notify(t("...", { path, count }), "warning")` once per provider and path; suppress repeats until that path is subsequently listed without truncation, then allow a new warning if it truncates again. Use the returned item count. Add one English message in `src/shared/i18n/en/` and follow epic translation-at-close rules. Import `ui` directly, as `src/renderer/content/open-with-default-app.ts:25` and `src/renderer/content/source-recovery.ts:12` do. Return only actual items; add no marker or tree-view rendering.
- [ ] **Write capabilities:** `writable` is a getter true if the current accepted owner's `moduleService.providerTreeCapabilities(root, type)` has at least one of `mkdir`, `rename`, `delete`; unknown or revoked means false. Use optional function-valued getters for `mkdir`, `rename` and `deleteItem`, returning `undefined` unless that individual capability is true; these call methods bound to the proxy and recheck the current owner and capability immediately before dispatch. Menus and action code re-read methods at use time, so no always-present stubs are needed. No `deleteItems`: existing `plural-actions.ts:117–149` uses `deleteItem` per item and reports individual failures. Translate a known cached href to its exact board path for delete; unknown href fails closed. `mkdir` and `rename` use board paths from the root-safe UI join; forward `treeMkdir`, `treeRename`, `treeDelete` and preserve errors. No `addItem`, import, move, search or unrelated local-file actions. A first list acquires the lease and its capability announcement; a later menu read sees it. If a lease loses capabilities or the owner changes, getters immediately hide writes; board enforces per-connection permissions.
- [ ] **Cancellation, errors, lifecycle:** retain an `AbortController` per pending list/stat and pass its signal to `requestTree`; remove it when settled and abort all on `dispose` and owner invalidation. `ITreeProvider.list/stat` currently accept no caller signal, so do not claim collapse cancels an individual request; US-2246 may add caller cancellation. Extract the shared provider-result and transport error mapping from `ProxyProvider.ts:66–90,144–165` into a focused content-owned helper used by both proxies, preserving its existing behavior and `ProviderOperationError` identity; do not duplicate a wire envelope or swallow errors. Root failures already reach tree error state. US-2246 owns nested-list error display and retry (currently `provider-tree-store.ts:230` turns failures into empty children), per-folder loading indicators, missing-state recovery, local-action gating and late-result cancellation. Dispose clears controllers, indexes and subscriptions; no service ownership is retained.
- [ ] **Navigation capability:** set `navigable = true` for board roots, as board paths have parents and folder navigation is required by the epic; `hasTags = false`, `hasHostnames = false`, `pinnable = false`. US-2246 must replace local `fpDirname`/filesystem root handling in `ExplorerEditorModel.ts:205–215` and `ExplorerSecondaryView.ts:366–401` with provider-aware root navigation and preserve descriptor/config; do not expose those local-only controls for a board until that work lands. No search implementation.
- [ ] **Guardrails:** `ProxyTreeProvider` owns translation, per-list ownership enforcement, capability projection and cache; `registry.ts` owns accepted type ownership; `scheme-registry.ts` owns scheme ownership; US-2244 host owns wire validation; `tree-provider-link.ts` owns category encoding; the focused tree path helper owns joining paths. `eslint.config.mjs:679–682` prohibits content importing components/scripting or non-seam editors; use direct allowed imports, no new exception, dynamic import or bypass wrapper. `scripts/typecheck-strict.mjs` includes content; null-check repairs there are type-only unless explicitly recorded as behavioral changes. No new protocol code or board policy outside shared board/registries; no growth in roadmap §2.3 god files. This task changes no `window.persephone`; if implementation changes it despite scope, bump `BOARD_BRIDGE_VERSION` and add the history line.

## Concerns

- The board's href need not encode a reversible path in a format core understands. Navigation-by-href and delete work only for currently indexed items; an unknown href is an explicit failure. Re-list after writes to refresh mappings. Directory names differing only by case may collide in the current Windows `hrefKey` (`src/renderer/components/tree-provider/href-utils.ts:4–10`); live checks must expose this limitation and US-2246 must address case-sensitive remote trees if encountered, without changing local comparison behavior here.
- Tree list calls can take indefinitely until cancellation; current tree has no per-folder loading state, and `loadChildren` suppresses errors. US-2246 must expose nested errors and add pending/recovery UX; Category view already has a loading state. A control timeout cannot roll back an already-started board write.
- Config comes from persisted JSON; opaque means core only serializes it, never interprets it. Reordered object keys match, and `undefined`/absent config and `null` share an identity by design. Board authors must not persist credentials there.
- If one board declares the same scheme for two of its types, `boardSchemeOwner` and the per-type declarations cannot distinguish which type won the scheme registration; opening that href may route to the first registered type. This is a known limitation and does not add scheme-to-type registry metadata in this task.
- There are no unresolved design choices for implementation. US-2243 and US-2244 must land first; reconcile their final exported types and names with these contracts.

## Acceptance Criteria

- [ ] One namespaced matcher makes an inert recoverable shell; only the currently accepted, trusted owner with `tree: true` receives calls, and absent/untrusted/rejected declarations report existing typed resolution errors and can recover.
- [ ] Stable descriptor identity survives restore and separates distinct non-null configurations; board paths, hrefs, metadata, root icon, breadcrumbs, file opening and category links round-trip, including `/` and Unicode.
- [ ] Each returned href uses a scheme listed for the accepted type and owned by the accepted board; any failure rejects the whole list. A truncated result emits one warning per provider/path until a later untruncated list resets it.
- [ ] Each write appears only when its capability is announced and remains authorized at execution. Unknown capability hides writes, lease loss removes them, and delete maps href to path without guessing. No search or cross-tree transfer.
- [ ] Requests use the existing transport and error types; disposal cancels pending reads. Root errors reach the existing error state; US-2246 owns nested errors, per-folder loading, missing recovery and provider-aware Explorer root navigation.
- [ ] Required typecheck, lint and production build pass; Claude's live verification with US-2248 is recorded. No unit tests or protocol duplication.
