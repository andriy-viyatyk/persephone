# US-1728: Voice typing — live text as you speak

## Goal

When a `speech.transcribe@1` provider advertises `features: ["live"]`, voice typing requests live transcription and inserts each committed segment into the focused editable target as it arrives, while showing replaceable draft text in its overlay. Preserve final-result behavior for providers without the feature and reconcile live segments with the final result without duplicate insertion.

## Background

- `src/renderer/ui/voice-typing/VoiceTypingController.ts` owns provider discovery, audio capture, service-channel handling, session state, stop/cancel, and final text insertion. `openChannel()` currently picks the first v1 provider from `api.getBoardServiceProviders("speech.transcribe")` and opens `type: "transcribe"`; `BoardServiceProvider` in `src/ipc/board-bridge-channels.ts` exposes only `provider`, `title`, `version`, and `boardName`, not feature metadata. The consumer therefore needs a `type: "describe"` request to discover `features` before it opens the transcription request.
- The controller's `observeChannel()` currently handles status, final `result.text`, and terminal `error`. `endChannel()` flushes/stops capture, sends `end`, and remains in transcribing state awaiting the provider. Extend that listener to accept `draft` and `segment` messages through `result`, including messages delivered after `end`.
- The controller's current `insertResult()` trims Whisper padding, calls `api.insertVoiceTypingText({ sessionId, text })`, reports clipboard fallback, then finishes the session. `src/main/open-window.ts::insertVoiceTypingText()` resolves the active element in `session.target.focusedFrame` at each insertion (text input/textarea selection, contenteditable selection, and Monaco `editContext`), inserts via `target.insertText()` in the main frame or `document.execCommand("insertText")` in a child frame, and prefixes one space when the character before the caret is non-whitespace. If the target is gone or nothing editable is focused, it writes the text to the clipboard and clears the main-process voice session. On successful insertion it also clears that session. Repeated segment insertion therefore needs this session-clearing behavior adjusted so the channel's later segments and result remain authorized.
- The main process captures a `WebContents` when the shortcut starts (`src/main/open-window.ts::toggleVoiceTyping`); it does not capture a particular input or frame. Its existing final insertion checks focus at insertion time, so a later segment should use the same per-insertion focus resolution. If the original input loses focus but another editable element is active in that same captured WebContents, today's final insertion goes to the newly active element; if no editable element is focused or the captured WebContents/input is gone, insertion falls back to the clipboard and clears the voice session. `insertVoiceTypingText()` currently accepts calls only while main-process state is `transcribing`, which means live insertion during recording must allow the captured active session while its state is `recording` too. Avoid redirecting text to a different WebContents.
- `src/renderer/ui/voice-typing/VoiceTypingOverlayView.ts` renders status, duration, and the audio meter from `VoiceTypingOverlayState`; its `details` span is currently used for duration during recording and cleared while transcribing. `VoiceTypingOverlayView.css` styles three spans, with the third reserved for the meter. Add draft state/rendering without inserting draft text into the target. Overlay text belongs to `voiceTyping` in `src/shared/i18n/en/voiceTyping.ts`; `doc/standards/localization.md` requires English source catalog entries, `t()` at UI call sites, and keeping each sentence in one catalog message.
- Voice typing settings live in `src/renderer/api/settings.ts` (`AppSettingsKey`, `settingDescriptions`, `defaultAppSettingsState`, load normalization) and the General > Voice Typing section in `src/renderer/editors/settings/settings-catalog.ts` and `src/renderer/editors/settings/sections/SettingsSections.ts::VoiceTypingSettingsSectionView`. Today only `voice-typing.shortcut` is exposed there. Add an opt-in duration setting named `voice-typing.auto-stop-silence-ms`, default `0` (disabled), with validation and UI alongside the shortcut.
- `assets/guides/agents/speech-transcribe.md` defines optional `draft` and `segment` messages, ordered committed utterances, optional `live` request opt-in, and says provider `result.text` is the nonempty segment texts joined with one space. After `end`, `transcribing`, remaining drafts/segments, and then exactly one result/error may arrive. The provider's 1.1.0 implementation in `C:/projects/persephone-boards/boards/speech-to-text/scripts/service.mjs` advertises `features: ["live"]`, trims live inference text, sends draft/segment events and assembles final text from committed segment text. It is read-only context for this task; do not edit that repository.
- In `src/renderer/ui/voice-typing/VoiceTypingController.ts`, AudioWorklet `level` messages carry the current RMS level and update `this.level`; they are available independently of provider draft/segment messages. Use those measured levels for acoustic quiet detection, not event inactivity.
- The Speech to Text provider checks `checkCaller(info)` before handling `describe` in `C:/projects/persephone-boards/boards/speech-to-text/scripts/service.mjs` (`persephone` is accepted only when its caller approval policy allows the host interface). A refused describe therefore yields no feature description; this task treats that and any failed/malformed describe as non-live and continues with an ordinary v1 transcription request.
- `src/renderer/core/utils/utils.ts::toClipboard()` writes through Electron's native clipboard. It is the existing renderer-side path for one final buffered live fallback write; it does not rely on the cleared main-process voice session or `navigator.clipboard`.
- US-1724 established the focused-input insertion behavior and tested Monaco, a board prompt, and a browser webview input. US-1725 made microphone startup parallel with provider startup and buffered PCM until the provider accepts; keep that startup behavior intact. Their records are in `doc/tasks/completed.md`; there are no separate task folders for US-1724 or US-1725.
- EPIC-134 phase 2 also tracks Agent Chat live insertion and provider-side left-context work separately. This task covers only Persephone voice typing.

### Current behavior → planned behavior

```ts
// Current VoiceTypingController.openChannel()
openMessage: { type: "transcribe", format: { encoding: "pcm-s16le", sampleRate: AUDIO_SAMPLE_RATE, channels: 1 } }

// Planned: after a describe request confirms features includes "live"
openMessage: { type: "transcribe", format: { encoding: "pcm-s16le", sampleRate: AUDIO_SAMPLE_RATE, channels: 1 }, live: true }
```

```ts
// Current observeChannel(): final result is the only text insertion
if (value.type === "result" && typeof value.text === "string") void this.insertResult(session, value.text);

// Planned: committed segments insert incrementally; result inserts only an undelivered suffix
if (value.type === "segment") void this.insertSegment(session, value);
if (value.type === "result") void this.finishLiveResult(session, value.text);
```

## Implementation Plan

- [x] In `src/renderer/ui/voice-typing/VoiceTypingController.ts`, add a per-controller cache keyed by provider id plus interface version for the describe outcome, including a negative/non-live outcome. Reuse it for later dictations in the same app session. On a cache miss, open the describe channel and await its description/close outcome; validate `features` as an array and opt in only when it contains the exact string `"live"`. A refused, failed, timed-out, closed-without-description, or malformed describe resolves to non-live and continues with the ordinary transcription open. The provider gates describe through its caller-approval policy, so refusal must not block voice typing. Keep `openChannel(session)` (provider selection, describe, and transcribe open) in the existing `Promise.all([openChannel(session), openMicrophone(session)])` startup so description runs in parallel with microphone acquisition; preserve `channelReady` and PCM buffering (`openProviderAndCapture()`, `drainPending()`).
- [x] In the same controller, extend the provider message type guard to handle `draft`, `segment`, and `result`. Track the current draft by `utterance`; a new draft replaces the displayed draft, and that utterance's segment clears it. Keep the listener active until terminal `result` or `error`, even when the user has sent `end`; do not treat `status: transcribing` or a temporarily quiet channel as completion.
- [x] Serialize asynchronous segment insertions in arrival order. Trim segment text, ignore empty committed text, and join successfully inserted segment strings with one literal space for reconciliation. Count a segment as inserted only when the IPC result is `{ copied: false }`. At `result`, trim its text and compare it with the joined inserted text: if equal, insert nothing; if it starts with the joined inserted text followed by exactly one contract separator (`" "`), the remainder after that separator is undelivered. With no inserted segments and no buffered segments, the full trimmed result is undelivered. If it matches neither form, do not replay the whole result; report the contract mismatch and finish without risking duplicates. Ensure result processing waits for queued segment insertions before reconciling and finishing.
- [x] Handle live clipboard fallback without dropping text. Add a `deferClipboard` option to the voice insertion IPC request and use it for segment insertions: when no editable target is available, `src/main/open-window.ts::insertVoiceTypingText()` returns `{ copied: true }` and clears the main-process session as today, but does not copy that one segment yet. The controller then stops further live insertion and buffers that segment plus every later segment. At `result`, form the expected complete text as joined inserted segments, one space, then joined buffered segments (omitting an empty side). If `result.text` equals that text, copy the buffered side once; if it starts with the expected text plus one space, append the remaining suffix to the buffer before copying. If it mismatches, retain and copy the buffered segments, report the mismatch, and never copy already-inserted text again. Call `toClipboard()` from `src/renderer/core/utils/utils.ts` once with the full undelivered buffer and show `t("voiceTyping.copied")` once. This renderer-side write remains available after main-process session cleanup. Keep the existing immediate main-process clipboard fallback for non-live final-result insertion.
- [x] Update `src/main/open-window.ts::insertVoiceTypingText()` and its IPC contract to permit segment calls while the session state is either `recording` or `transcribing`; keep the captured `WebContents` and current per-call active-frame/element resolution. Do not clear `voiceTypingSession` after successful live insertion; clear it when transcription terminates or when a non-deferred fallback is used. A deferred fallback clears the main session, after which the controller buffers rather than attempting further insertions. Focus within the captured WebContents is resolved anew for each segment, so if the original input loses focus but another editable element is active in that WebContents, the segment goes to that current caret; if no editable element is focused or the target is gone, use the buffered clipboard path. Never redirect to another WebContents.
- [x] Update `src/renderer/ui/voice-typing/VoiceTypingOverlayView.ts` and `VoiceTypingOverlayView.css` to expose draft text as a distinct, single-line overlay detail while recording/transcribing, not as committed text in the input. ## Concerns / Open Questions

- **Auto-stop decision (resolved 2026-10-26):** “Silence” means low microphone RMS level, not a gap in provider messages: draft/segment events can be absent for up to the provider's 25-second utterance cap while the user is still speaking, so event inactivity could stop mid-sentence. Auto-stop requires both sustained quiet (`level < max(0.005, 20% of median RMS over committed utterance audio)`) for the selected duration and no pending utterance: at least one segment must have arrived, and every utterance with a draft must have since committed. Before the first segment, auto-stop cannot fire. In a noisy room the RMS level may stay above the threshold and auto-stop may never trigger; that is the safe failure mode. Settings offer Off, 2, 3, 5, or 10 seconds; Off is the default. It uses the same stop/flush/end path and sends main-process state `transcribing` via `setVoiceTypingState` as shortcut stop.
- **Clipboard fallback (resolved):** For live segments, a `{ copied: true }` response stops further live insertion and starts buffering undelivered segment text. The main process does not immediately overwrite the clipboard in deferred mode. At `result`, append any contract-proven remainder and write the complete undelivered text once via `src/renderer/core/utils/utils.ts::toClipboard()`, then show the existing copied notice once. This survives main-process session cleanup and avoids losing later segments. Non-live final-result fallback keeps its current immediate clipboard behavior.
- **Final result mismatch:** The contract makes the result equal to the nonempty segment texts joined with one space. The plan avoids whole-result replay after live insertion and only permits suffix insertion when an exact segment-prefix match proves the suffix is undelivered. If a provider violates that contract, prefer no duplicate replay and surface/log the mismatch rather than attempting fuzzy text deduplication.
- **Describe/cache decision (resolved):** Cache each provider's validated live-feature description by provider id and interface version for this app session. Run a cache-miss describe handshake in parallel with microphone startup. The provider applies caller permission before serving describe; refusal, transport failure, missing response, or malformed description means non-live and voice typing continues with a normal request. The renderer must not surface describe failure as a dictation error.
- **Cancellation (resolved):** Escape after one or more segments have been inserted leaves that text in place; there is no undo. It cancels the remaining stream and discards buffered text, with no further insertion or clipboard write.
- **Draft size and caret behavior (resolved):** Draft preview is a bounded single line showing the last approximately 80 characters, with a leading ellipsis when truncated. The user may type or move the caret between segments; each segment is inserted at the caret currently active in the captured WebContents, which matches the existing insertion behavior and is acceptable.

## Acceptance Criteria

- [ ] Providers advertising `features` containing `"live"` receive `live: true`; providers without it receive an ordinary v1 request and retain today's final-result-only behavior.
- [ ] Each nonempty committed `segment` is inserted in arrival order as it arrives, using the existing insertion behavior for text inputs, textareas, contenteditable targets, and Monaco; words are separated by one space as needed.
- [ ] The latest draft is visible in the overlay, replaced by a newer draft, never inserted into the focused target, and cleared when its utterance commits.
- [ ] A live result equal to the joined committed segment texts causes no duplicate insertion. A final result containing provably undelivered text inserts only that text; when no live segments were delivered, the full result is inserted once.
- [ ] Drafts and segments arriving after `end` continue to be processed until `result`/`error`; stop, cancel, failure, and completion clear overlay draft state and release capture/session resources. Escape after segments were inserted leaves them in place and inserts/copies nothing further.
- [ ] Optional auto-stop is configurable in General > Voice Typing with Off, 2, 3, 5, and 10 second choices; Off is the default. It requires sustained RMS quiet below `max(0.005, 20% of median committed-utterance RMS)` and no pending draft utterance, and never fires before the first segment. It follows shortcut stop's transcribing/flush/end path.
- [ ] Once a live segment insertion falls back (`{ copied: true }`), that segment and all later undelivered segments/result suffix are buffered and copied once at `result` through `toClipboard()`, with one existing copied notice; no text is lost.
- [ ] Describe results are cached by provider id/version for the app session. Describe runs alongside microphone startup; refusal/failure/malformed output selects non-live mode without surfacing an error.
- [ ] Draft previews remain one line and show at most the last approximately 80 characters. Segments use the caret currently active at each insertion time, including after user typing or moving the caret.
- [ ] Focus changes are handled against the captured WebContents with per-segment current-focus lookup; destruction or loss of editable focus switches live insertion to the buffered clipboard path and prevents subsequent duplicate insertion.

## Fixes after implementation

- The main process rejected `describe` on the host service channel (`module-service-supervisor.ts::connectHostServiceChannel` allowed `transcribe` only), so live mode was never enabled and auto-stop never armed. It now accepts `describe` too.
- A failed or timed-out describe is no longer cached as "not live"; only a real description is cached, so a transient failure is retried on the next dictation.
- The auto-stop quiet threshold is computed once per committed segment instead of re-sorting all speech levels every 150 ms.
