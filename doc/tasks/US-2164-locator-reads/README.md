# US-2164: Locator reads and waitForFunction

[EPIC-206](../../epics/EPIC-206.md) · Proposals D4 and D5 · Planned

## Goal

Add bounded locator reads and an in-page predicate wait to the browser automation API, using the shared locator and access paths. This is an implementation plan; no implementation is included here.

## Background

- US-2160 and US-2161 are staged. `automation/page-scripts.ts` owns selector parsing; `selector-execution.ts` owns host execution and obtains Chromium AX facts when a selector contains `role=`. `evaluateWithCandidates` returns by value; `evaluateCandidateObject` returns a remote object. `resolveElementLocator` currently accepts strings and `{ ref }`; US-2162 will compile its object form there. Implement this task after US-2162 without changing its parser or document.
- `queries.ts`'s five existing reads take the first query candidate or call `callOnRef`; `getElementText` returns `textContent`. Query mode returns hidden CSS matches, but `text=` has its own displayed-element filtering and area/depth ordering. Therefore “all matches” below means the resolver's query result, not a promise to override an engine's semantics. `runOnLocator` filters visible matches before strictness and is unsuitable for these strict reads without changing existing actions. Use `evaluateWithCandidates` and `callOnRef` instead.
- `snapshot.ts` uses `Accessibility.getFullAXTree`, drops ignored nodes and some wrappers, and can substitute descendant text for a pointer-generic node's displayed name. `selector-execution.ts` uses `Accessibility.queryAXTree` for requested roles. Bulk role/name use Chromium AX facts as the `role=` engine does; absent/ignored AX nodes are null. A pointer-generic snapshot line (`generic … [cursor=pointer]`) can show descendant text while `query` reports the AX name, often empty. Document that distinction; leave snapshot formatting unchanged.
- `BrowserEditorFacade` has 711 lines and contains the current read descriptors and forwards reads through `runHostOperation` with `passive: false, tip: true`. It is not a roadmap §2.3 god file; keep additions thin. `AutomationSurface` handles readiness and activity; its `evaluate` uses `passive: false, tip: true`. Browser, board and `WindowScreen` share `BROWSER_AUTOMATION_MEMBERS`, but existing five reads and `waitForSelector` are browser-only; board and window screen do have `evaluate` and `waitFor`. The browser page access path in `PageWrapper.ts` uses `agentMayAccessBrowserPage`; board has its own descriptor restriction and whole-window `restrictedWindowScreen` rejects visible private pages.
- Existing `waitFor` defaults to 10,000 ms and clamps to 595,000 ms; action timeout caps at 28,000 ms. The test host defaults to a 30,000 ms request and proxies method names through `app-proxy.ts`; arguments must be JSON. Its guide is now split under `assets/guides/agents/web-app-tests/`, not the former `web-app-tests.md` path. No runner change is needed.

## Implementation plan

### 1. Contract and ownership

- [x] Add `src/renderer/automation/locator-reads.ts` as owner of the new read semantics and page-authored snippets; retain the existing reads and `getText` behavior in `queries.ts`. Add `src/renderer/automation/wait-for-function.ts` as owner of predicate validation, scheduling, timeout and navigation errors. Reuse `resolveElementLocator`, `evaluateWithCandidates`, `callOnRef`, `VISIBLE_FN`, `CdpSession` and existing automation activity/readiness. Do not introduce a transport, selector parser, board policy, import-zone workaround or unit tests.
- [x] **Decision:** all eight reads accept `IBrowserElementLocator` and `{ nth?: number; tabId?: string }`, with `query` also accepting `fields`. `nth` is a zero-based non-negative integer selecting from the resolver's query list before the read, count, bulk ordering and cap; an out-of-range index produces an empty list. Omitted `nth` retains the full query list. A ref is a single-item list: `nth: 0` selects it and a larger index yields an empty list; resolve the ref first so stale-ref errors remain. Reject invalid `nth`. Normalize at `AutomationSurface` with `resolveElementLocator`; never interpret caller selectors elsewhere. Selector resolution remains in the target's default document; frame refs address their own frame.
- [x] **Decision:** reads are immediate and do not retry. `count` returns the selected query-list length (a valid ref counts 1); `allInnerTexts` returns its `innerText` in resolver order (empty array on no match). `isVisible` returns false for no match, but throws for more than one match, including hidden matches. `isEnabled`, `isChecked`, `innerText`, and `boundingBox` also reject zero or multiple matches, except `boundingBox` returns null for no match or non-visible element. Strict-mode errors name the match count and suggest `{ nth }` or `nth=`; an `nth` selection cannot be ambiguous. This follows Playwright's strict locator rule. `innerText` returns untrimmed `innerText` and rejects non-HTML elements; do not change `getText`/`textContent` alias.
- [x] Reuse `VISIBLE_FN` for visibility (positive dimensions, computed display and visibility). For enabled state implement Playwright-style native disabled form controls including disabled fieldset/first legend and disabled option/optgroup, plus inherited `aria-disabled="true"`; other elements are enabled. Checked state accepts native checkbox/radio or an element with a valid `aria-checked` on checkbox, radio, switch, menuitemcheckbox or menuitemradio roles; `true` is checked, `false` unchecked; mixed and unsupported elements throw a clear error. `aria-pressed` is a toggle-button state, not checked. Use the same state routines for scalar and bulk fields; bulk `checked` is null for unsupported/mixed elements instead of throwing.
- [x] `boundingBox` returns `{ x, y, width, height }` in CSS pixels relative to the main target viewport, not document scroll coordinates. Use `getBoundingClientRect` and existing `FRAME_OFFSETS_FN`/`createInputSession().mapPoint` for same-process frame refs; account for iframe borders. `input-session.ts` only sums supplied offsets, so reject OOPIF refs clearly instead of presenting frame-local coordinates as main-viewport coordinates. Hidden/zero-size returns null; offscreen visible rectangles may have negative coordinates.

### 2. Bulk query and AX/ref correlation

- [x] **Decision:** `query(locator, { fields?, nth?, tabId? })` returns `{ matches: object[], truncated: boolean }`, capped at 200 selected matches. Default fields are `role`, `name`, `text`, `visible`, `enabled`, `checked`, `tag`, `ref`; opt-in `value` and `attributes`. Validate an array of unique known field names before any page work; reject unknown, duplicate and non-string fields with a useful list. Empty fields is allowed and returns empty objects. Only requested keys appear. `text` is trimmed `innerText` capped at 1,000 characters; `value` is the string value or null; `tag` is lowercase localName; attributes are a name/value object capped at 50 attributes and 1,000 characters per value. Return explicit null for unavailable role/name and checked. These bounds do not prevent outer call `maxLength` truncation; document raising it.
- [x] Re-read `src/renderer/automation/selector-execution.ts` after US-2162 lands: that task extends its private `executeWithCandidates` path to resolve `ref=` steps host-side alongside `role=` AX facts. Add a third exported entry (or option) on that same private path for a repository-authored body returning a capped remote array and total/truncation information. Do not add a parallel evaluate path: `role=` and `ref=` must work for bulk capture and all reads. Enumerate the collection's numeric properties using CDP `Runtime.getProperties` and retain element object IDs and order. For direct refs, use `resolveRef` and `getRefSessionId`; preserve the frame-prefixed ref. Extract page fields in one page invocation over those same objects, never rerun the caller selector. Release collection and every acquired remote object in `finally`, including partial failures; bound parallel CDP work to 8. Abort clearly on navigation or a detached candidate instead of returning miscorrelated rows.
- [x] When `ref`, `role`, or `name` is requested, call `DOM.describeNode` for each retained element in its session, validate the backend node ID as `page-model-refs.ts` does, and create ordinary `e<backendNodeId>` refs for selector results. Do not import the editor-owned marker registry into automation; a small helper in `locator-reads.ts` owns this conversion and uses the existing `ref.ts` format. No DOM marker attributes or new protocol. **Decision:** only when role or name is requested, obtain one `Accessibility.getFullAXTree` per call for the relevant session and join by backend node ID; select the non-ignored AX node for the element. This single strategy avoids a threshold and up to 200 separate AX requests. Return the Chromium role/name facts matched by `role=`, with null for missing or ignored nodes; do not derive names in page JavaScript. For an exposed row, its role and exact name can be used in `role=<role>[name="<name>"s]` (escape the name as a selector string). Frame-ref calls use the correct session and frame-scoped ref; no cross-frame selector expansion.
- [x] Be explicit about cost: this is one public call and one candidate selection, not literally one CDP round trip. AX tree retrieval and up to 200 node descriptions add host-side CDP calls only when requested. `role=` may additionally run its existing preflight. Ensure document-order bulk output by sorting captured candidates by `compareDocumentPosition` in the page before capping, including `text=` results; scalar `allInnerTexts` retains resolver order. This deliberate bulk ordering does not change selector behavior elsewhere.

```ts
// Before: each browser read directly selects the first candidate.
return evaluateWithCandidates(cdp, locator.selector, "(resolve) => resolve('query')[0]?.textContent ?? null");
// After: new reads use the same resolver, with their own explicit cardinality.
return evaluateWithCandidates(cdp, locator.selector, `(resolve) => {
    const matches = resolve('query'); // apply validated nth before the strictness check
    if (matches.length > 1) throw new Error('Strict locator matched ' + matches.length + ' elements; use { nth } or nth=.');
    return matches.length ? visible(matches[0]) : false;
}`); // insert VISIBLE_FN into the generated repository-authored body
```

### 3. Predicate wait

- [x] **Decision:** `waitForFunction(fn, options?)` accepts a function in an in-app script (serialize using `toString()`) or a function-source string over `call`; `args?: JsonValue[]`, `timeout?: number`, `polling?: 'raf' | number`, `tabId?: string`. Default timeout 10,000 ms; validate finite non-negative numbers and clamp to 28,000 ms, leaving room under the default 30 s test-host request. `polling` defaults to `raf`; a numeric interval is finite 10–10,000 ms. Reuse/extract `queries.ts` JSON argument validation into an automation helper shared by `evaluate` and the wait; do not change evaluate semantics.
- [x] Evaluate the source as a function expression once in the target page, reject non-functions and syntax errors, and call with spread args immediately. Await each predicate result, with no overlapping invocations. For `raf`, race one animation frame with a 100 ms fallback timer each cycle and cancel the loser; numeric polling uses a timer. Return the first truthy JSON-serialisable result by value, preserving ordinary JSON types; reject unsupported/cyclic values clearly. Propagate predicate exceptions with context. No closure variables from the script host survive serialization.
- [x] Establish a host deadline as well as page timers so a pending async predicate or a throttled background page cannot leave the call waiting indefinitely. Race the CDP promise against a host timer, clear timers on all settled paths, and make page scheduling stop on deadline; a currently executing synchronous infinite loop or unresolved user promise cannot be forcibly cancelled, and any caller-code side effects already in flight can continue. Map CDP context-loss errors to `Page navigated while waiting for function.`; move the two existing `isPageModelContextLoss` message checks from `editors/browser/page-model-reply.ts` into `src/renderer/automation/context-loss.ts` and update its existing caller, keeping other errors intact. Page navigation must win over a later timeout when the context is destroyed.
- [x] Route through `AutomationSurface.run` with exactly evaluate's readiness/activity/tip policy and existing descriptor access gates. This is caller-authored page code with the same trust and mutation capability as `evaluate`; mark its descriptor caution accordingly. Expose on browser, board and app window, the three hosts already exposing `waitFor`/`evaluate`. `waitForSelector` itself is browser-only.

```ts
// Before: shared surface exposes evaluate and waitFor.
evaluate(code, options) { return this.run('evaluate', options?.tabId, () => evaluateInTarget(this.target, code, options), { passive: false, tip: true }); }
// After: same gate and activity path, implementation owned by automation.
waitForFunction(fn, options) { return this.run('waitForFunction', options?.tabId, () => waitForFunction(this.target, fn, options), { passive: false, tip: true }); }
```

## Concerns

- AX and refs require multiple CDP operations and can race page mutations. Correlate one captured element set by backend ID, fail on navigation/detachment, and release objects on all paths. Null is intentional when no corresponding unignored AX node exists. Pointer-generic snapshot lines may show descendant text in place of the AX name; query retains the AX name used by `role=`.
- Frame translation must not silently return wrong coordinates; OOPIF bounding boxes are explicitly rejected because the existing input mapper only adds supplied same-process offsets. `text=` query mode already filters and sorts differently from CSS; neither `count` nor `allInnerTexts` overrides that engine.
- **Decision:** `evaluate` key-order change is excluded: `evaluateStringCode` and function evaluation return arbitrary by-value results, including non-JSON CDP values. Unconditional `JSON.stringify` would change those results and errors. Existing help asks callers to stringify explicitly when order matters.
- A page-side timer cannot interrupt synchronous caller code; host timeout bounds the wait response but cannot roll back side effects. Hidden-tab timers can themselves be throttled; the host deadline remains authoritative.
