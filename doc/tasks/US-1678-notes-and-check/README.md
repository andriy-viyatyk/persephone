# US-1678: Translator notes and i18n check hardening

## Goal

Add concise English translator notes to ambiguous catalog messages before language drafting. Extend `npm run i18n:check` to report pack completeness and source-hash state, reject malformed or corrupted translations, and validate board language packs with the board host's rules.

## Background

`src/shared/i18n/en/` contains 19 area catalogs and 1,524 messages; `EnglishCatalogEntry` in `src/shared/i18n/en/common.ts` already supports `{ message, note? }`. The catalogs currently have 58 notes. G2 calls for notes where short labels depend on display context, a word could be a verb or noun, or a placeholder's value is not obvious. Notes are English, describe where/how the message appears, and must be no longer than 15 words.

`package.json` maps `i18n:check` to `node scripts/i18n-check.mjs`. That launcher uses `esbuild.buildSync()` with `bundle: true`, `platform: "node"`, `format: "esm"`, and invokes `scripts/i18n-check-entry.ts` with the CLI arguments. The entry currently reads and validates `.lang.json` files and checks pseudo-locale completeness. It computes missing and stale counts privately in `reportPack()`.

US-1676's shared audit helper is present at `src/shared/i18n/audit-pack.ts`. Reuse `auditLanguagePack(pack, area?)`: absent hashes increment `unverified`; only present hashes that differ from `hashEnglishMessage()` are stale. Do not redesign it. `validateLanguagePack()` is the existing source of app-pack validation warnings.

Board-pack checks currently live in `src/renderer/editors/board/board-i18n.ts`: JSON/object/messages shape, non-empty keys, `manifest.*` plain-string rules, message parsing, and non-default placeholder matching against the default table. US-1676's board-validation extraction is staged in `src/renderer/editors/board/board-i18n.ts`; it adds `validateBoardLanguagePack()` there. The staged `src/renderer/api/languages.ts` implements `languages.validateBoard()` by importing that renderer wrapper. `readBoardPack()` and `loadBoardI18n()` access renderer `app.fs`; `src/renderer/editors/board/board-manifest.ts` also imports renderer `app.fs` and settings, including in `readNormalizedBoardManifest()`. The esbuild checker is a Node script, so importing these renderer modules would bundle renderer API dependencies and cannot provide a safe Node-side filesystem path. Move the pure validation functions to `src/shared/i18n/board-pack.ts`, then have the board host, `validateBoardLanguagePack()`, and the checker call them. Keep the renderer wrapper and `languages.validateBoard()` behavior working after that move; `languages.ts` should need no import change if the wrapper remains exported from `board-i18n.ts`.

3. **Add one shared broken-text check for app and board packs.** Add `src/shared/i18n/broken-text.ts` with a pure message-check function and use that same function from `scripts/i18n-check-entry.ts` and the board-pack report; do not copy the checks into the script. For every accepted translated message, inspect each string form against its corresponding English plural category, falling back to English `other` when that category is absent. For a plural message, report every category in `new Intl.PluralRules(code).resolvedOptions().pluralCategories` that the translation does not supply; a missing `other` category is fatal. Fail if a form contains U+FFFD. Also fail on an in-word question mark with `/(?<=[\p{L}\p{N}])\?(?=[\p{L}\p{N}])/u`. Count `?` in the translated form and English form; allow one extra `?` only when it is sentence-final (optionally followed by spaces or closing punctuation), and fail if any remaining count exceeds English. This permits French spacing and languages that phrase a sentence as a question while catching replacement characters between letters or digits.

   Detect UTF-8 decoded as Windows-1252 using the continuation class `C` below. Flag `\u00C2-\u00DF` followed by one `C` character (two-byte UTF-8), or `\u00E0-\u00EF` followed by two `C` characters (three-byte UTF-8, including CJK and Korean). The exact continuation class and executable regex construction are:

   ```ts
   const C = String.raw`[\u0080-\u00BF\u0152\u0153\u0160\u0161\u0178\u017D\u017E\u0192\u02C6\u02DC\u2013\u2014\u2018-\u201E\u2020-\u2022\u2026\u2030\u2039\u203A\u20AC\u2122]`;
   const BROKEN_UTF8_MOJIBAKE = new RegExp(
       String.raw`(?:[\u00C2-\u00DF]${C}|[\u00E0-\u00EF]${C}{2})`,
       "u",
   );
   ```

## Concerns

- The checker's esbuild bundle is explicitly `platform: "node"`; `board-i18n.ts` imports `src/renderer/api/fs.ts`, and `board-manifest.ts` imports renderer APIs too. Pure shared validation is required for both host parity and reliable checker bundling.
- Board language filenames and manifest declarations must use shared renderer-free normalization; duplicating part of `normalizeBoardLanguages()` risks checker/host disagreement.
- U+FFFD and mojibake checks must call the same pure function in `src/shared/i18n/broken-text.ts` for both app and board translations. The question-mark check compares each plural form with its corresponding English category, falling back to `other`; it detects in-word replacement and unexplained excess punctuation while allowing a sentence-final question mark.
- UTF-8 decoded as Windows-1252 commonly produces printable continuation characters, including `€`, `‚`, `ƒ`, `„`, `…`, `†`, `‡`, `ˆ`, `‰`, `Š`, `‹`, `Œ`, `Ž`, `‘`, `’`, `“`, `”`, `•`, `–`, `—`, `˜`, `™`, `š`, `›`, `œ`, `ž`, and `Ÿ`. Use the two shared regex alternatives from step 3, not a broad Latin-letter check.
- `assets/boards/*` may include files or non-board folders; only directories with `board-manifest.json` are roots for the default script.
- The 58 existing notes leave substantial review work. This inventory is the verified baseline; implementation must repeat the catalog-key/use-site audit and add any additional ambiguous entry discovered.

## Acceptance Criteria

- Every key in the note inventory has an English note no longer than 15 words that identifies its UI context; listed placeholders, including `{name}`, have their values explained.
- `npm run i18n:check` reuses `auditLanguagePack()` and reports per app pack missing, stale, and unverified categories; invalid app messages fail.
- App and board pack reports list missing locale plural categories; a plural message without `other` fails.
- App and board checks call the same `src/shared/i18n/broken-text.ts` function. It fails on U+FFFD, the exact in-word question-mark regex and excess-`?` rule, and both Windows-1252 mojibake alternatives. It matches `Ð¿Ñ€Ð¾`, `Ã©`, `â€”`, and `ä¸­æ–‡`; it does not match `São Paulo`, `Ñandú`, `¿Qué?`, `Ðaði`, `Größe`, `Ελληνικά`, `简体中文`, or `한국어`.
- `--boards <folder>...` reports each board and pack, including invalid entries, keys missing against the default pack, and broken characters; it matches host validation, including `manifest.*` exceptions and placeholder checks.
- `npm run i18n:check-boards` checks roots under `assets/boards/*`; explicit and wildcard paths such as `../persephone-boards/boards/*` work on Windows and Unix.
- Generated `en-XA` remains valid and complete; the ordinary checker still checks built-in packs and its optional user-pack directory.
