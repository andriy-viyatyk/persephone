# US-1792: Capability-like mechanisms inventory

## Goal

Map the current registration, discovery and invocation mechanisms for EPIC-140. This is an inventory of the checked-out source, not an implementation plan.

## Mechanisms

### Capability bus

The renderer-local bus resolves platform editor declarations and trusted or bundled board manifest declarations by id and major version. `list`, `handlers`, and `invoke` expose discovery and request/reply; priority, platform tie-breaking and registration order choose a winner. Board handlers use a page intent, while platform handlers run directly. A declared headless winner currently fails with `no-handler`. ([architecture](../../architecture/capability-bus.md#ownership-and-public-surface); [resolution](../../architecture/capability-bus.md#registration-and-resolution); [routing](../../architecture/capability-bus.md#request-routing))

### Board service interfaces

A board's `service` names its utility-process entry, `serviceInterfaces` declares providers, and `uses` declares consumer grants; these are distinct fields, not a manifest `provides` array. `services.list(id)` and `services.connect(id, {provider, version}, openMessage)` select exact versions. `service.openChannel` opens a channel to one's own service. Channels are ordered, bidirectional and bounded, with `send`, `onMessage`, close and backpressure; the older board service request API is request/reply. ([guide](../../../assets/guides/agents/boards.md#L19-L58), [types](../../../src/renderer/editors/board/board-api.d.ts#L280-L345), [renderer client](../../../src/renderer/api/module-service.ts#L337-L391))

Provider discovery is trust-filtered and connecting requires a granted exact `uses` declaration, provider declaration, service permission and current trust; grants are rechecked. Host consumers use a separate explicit allowlist with allowed open types, rather than arbitrary `uses`. The manifest `capabilities` array registers handlers; a `capabilities` permission disclosure is not a second functional gate. A caller's `appScripting` grant controls frame access to `call` and capability access. Service `uses` grants messaging to a specific interface/version, not the provider's own permissions; provider trust and `service` permission remain separate. ([bus architecture](../../architecture/capability-bus.md#registration-and-resolution), [frame gate](../../../src/renderer/editors/board/BoardWebview.ts#L1414-L1445), [service contract](../../../assets/guides/agents/speech-synthesize.md#L11-L22)).

## Overlaps and gaps

- Both the capability bus and service interfaces discover named board providers and send work, but have separate registries, trust rules, lifecycle and transports: page intents with one result versus utility-process channels with streaming. A winning `headless` capability currently returns `no-handler` ([bus](../../../src/renderer/api/capabilities.ts#L350-L395), [channel](../../../src/renderer/editors/board/board-api.d.ts#L297-L334)).
- The agent can discover bus entries directly, but cannot invoke them as capability paths; it can use full-privilege `script.execute`. It cannot directly discover/connect the service-interface channel API via `call`; board-root request/reply is a narrower script escape hatch and is not an `onChannel` stream ([descriptor](../../../src/renderer/scripting/ai-vision/namespaces/capabilities.ts#L4-L23), [root](../../../src/renderer/scripting/ai-vision/root.ts#L108-L154), [service API](../../../assets/guides/agents/boards.md#L802-L843)).
- A utility service has Node, not a browser frame, so it has no browser `getUserMedia` capture; speech contracts send audio from the consumer. Its injected host API has no direct capability or cross-board service client. A granted MCP endpoint is a separate, full-app-control route ([runtime](../../../assets/guides/agents/boards.md#L744-L768), [transcription](../../../assets/guides/agents/speech-transcribe.md#L9-L18), [host](../../../assets/module-service-host.mjs#L1065-L1081), [endpoint](../../../assets/guides/agents/boards.md#L19-L23)).
- Tool ids and service extension ids both use `author/name`-like slash naming; bus ids use dot names and optional `@major` at invocation. A bus `capabilities` declaration, service `serviceInterfaces`, and tool manifest describe different catalogs; `headless` in a bus declaration is metadata rather than a working service route ([validator](../../../src/shared/board-manifest-utils.ts#L5-L18), [tools](../../../assets/guides/agents/tools.md#L15-L17), [bus contract](../../../src/ipc/capability-bus-channels.ts#L35-L44)).
- PDF Viewer is discovered as an editor by file mask, not as `content.view` for `pdf`, in this checkout; the guide's PDF capability example is illustrative ([manifest](../../../../persephone-boards/boards/pdf-viewer/board-manifest.json#L25-L35), [example](../../../assets/guides/agents/boards.md#L935-L954)).

([channels](../../../assets/guides/agents/boards.md#L839-L854), [endpoint](../../../assets/guides/agents/boards.md#L19-L23))
