# US-2159: File-level hooks

## Goal

Add file-level lifecycle hooks to web-app tests under [EPIC-205](../../epics/EPIC-205.md), decisions 1 and 5–8. Keep the existing UI integration suite working unchanged.

## Background

[EPIC-205](../../epics/EPIC-205.md) links this task; roadmap B4 is in [web-app testing review](../../reviews/web-app-testing-review.md) §§3B and 5. EPIC-202 established modifiers, retries and located failures; EPIC-203 addressed browser automation; EPIC-204 added test windows, session pages, environment stops, `not-run`, and failure bundles. Their task documents are `doc/tasks/US-2147-runner-expect-matchers/README.md` through `doc/tasks/US-2156-failure-capture-bundle/README.md` (with their actual descriptive folder names). US-2157 and US-2158 are staged: shared polling lives in `src/test-host/poll.ts` and `poll-expect.ts`; `test-timeout.ts` supplies `run(callback, getStep)`, `assertActive`, and restart coordination; context operations are in `context-operations.ts`; descriptor validation is in `test-descriptor-validation.ts`.

`src/test-host/runner.ts` is **282 lines** now. `discover()` walks and imports `.test.mjs` files, validates their default descriptors, and turns errors into a `<module import>` descriptor. `run()` applies manifest and grep, computes rerun selection and `test.only`, starts the app/window, and owns the nested execution loop, skips, attempts, result building, and environment stop. `test-attempt.ts` creates a context and lifetime, takes a per-attempt page baseline, applies `--test-setup`, runs the body, captures a failure, then cleans pages. `context.ts` is the public types and a re-export; its implementation is already extracted. The timeout is `scaleTimeout(descriptor.timeout ?? configuration.testTimeout ?? 300_000, timeouts.scale ?? 1)`; 0 disables it. The CLI value flows via `src/main/test-mode/arguments.ts`, `controller.ts`, `launcher.ts` and `index.ts`.

`beginPageOwnership` snapshots pages and popups. Per-attempt snapshots taken after `beforeAll` naturally preserve file pages; `closePagesOpenedSince` in attached-selected mode closes only `ownedPages` and excludes `sessionPages` from page closing, while considering both for popup cleanup. `ctx.openBrowser` records ownership; `ctx.usePage` records adoption. File teardown needs the hook contexts' owned IDs and must not let adoption of a file-owned page exempt it from closure. `captureFailure` uses a baseline, context page sets and test-window scoping. `testFileLocation` finds the first test-file stack frame, but a timer-created `TestTimeoutError` has no guaranteed test-file frame.

`results.ts` currently persists failed identities and treats identities absent from discovered descriptors as stale on rerun. Its generic report already renders pseudo-result names, step, location, bundles and `cleanupErrors`; no report rendering change is needed. `src/test-host` is **not** in `scripts/typecheck-strict.mjs`; its existing strict-folder gate must remain green. `npm run test:ui` runs `integration-test/run.mjs` with tests in `integration-test/tests/` and suite extensions from `integration-test/test-setup.mjs`. Existing guide hub `assets/guides/agents/web-app-tests/index.md` is 9,668 characters; its limit is 10,000 and other guide pages are limited to 20,000.

### Shape of the change

Before:

```ts
const imported = await import(pathToFileURL(file).href);
discovered.push({ file, tests: exported });
await lifetime.run(() => descriptor.run(extendedContext), () => context._state.step);
```

After (illustrative; the extracted owners manage capture and scoped lifetimes):

```ts
const imported = await import(pathToFileURL(file).href);
discovered.push({ file, tests: exported, hooks: readFileHooks(imported) });
await lifetime.run(async () => {
    await invokeHook("beforeEach", hooks.beforeEach, extendedContext);
    await descriptor.run(extendedContext);
}, () => context._state.step);
// Capture a first failure, then invoke afterEach in a separate guarded async scope.
```

## Concerns

- **Hook timeout source line:** decision 7 asks for file:line, but `TestTimeoutError` is created in a timer in `test-timeout.ts`; `testFileLocation` only reads the thrown stack, and the timer stack generally has no suspended hook frame. Capturing an invocation stack in the host identifies the caller, not reliably the exported function definition or suspended line. Preserve the hook phase and last inner step, report the file without a fabricated line when no test-file frame exists, and retain exact file:line for normal hook throws. This is the closest reliable behavior without source parsing or protocol changes; the line requirement cannot be guaranteed for timeout errors by the existing mechanism.
- Async-local scoping prevents future host calls from the abandoned body while allowing the same context in teardown, but cannot undo an in-flight RPC or stop synchronous infinite loops. Extensions can perform work outside guarded context/adapter APIs; document that the runner cannot cancel arbitrary extension work. An afterEach timeout likewise leaves its own scope closed.
- A hook may adopt a pre-existing page or own a page also adopted by another hook. The owned-minus-session distinction above is essential in attached-selected mode; never close a user's adopted page just because it is in `sessionPages`.
- A stopped environment prevents reliable further hooks and cleanup; follow the existing environment-stop behavior instead of promising afterAll after a stop. Module import failure and file cleanup can each produce pseudo-results with no hook-defined source line.

## Acceptance Criteria

- Named hooks are validated at discovery; non-functions become `<module import>` failures. Hooks run only for files with runnable selected tests, in the specified order and contexts, with extensions, timeouts and retry semantics above.
- First failures are captured before teardown; afterEach executes under a separate bounded guard, stale body calls remain refused, errors and steps remain attributable, and an afterEach-only `test.fails` is a real failure. Ordinary hook errors show test-file location when present; timeout location limitation is explicit.
- File hooks have independent contexts, file page ownership survives each test and is cleaned after afterAll, including attached-selected and adopted pages. BeforeAll failure produces one failed pseudo-result and `not-run` runnable tests; afterAll failure produces one failed pseudo-result; environment stops and file cleanup are reported.
- Rerun selection expands saved hook failures to the file's descriptors and retains stale handling; logs and existing reports show the outcomes. Existing selection, skips, `test.only`, retries, setup and UI integration behavior remain compatible.
- `runner.ts` shrinks from 282 toward ≤190 lines; `context.ts` does not grow. No new protocol, bridge surface or `BOARD_BRIDGE_VERSION` change, import-zone bypass, unit tests or harness. Listed checks and live scenarios pass or their unavailable status is reported; guide limits are met.
