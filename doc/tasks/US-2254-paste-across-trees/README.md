# US-2254: Copy/paste across trees

[EPIC-218](../../epics/EPIC-218.md) | Planned | Depends on [US-2251](../US-2251-chunked-provider-writes/README.md), [US-2252](../US-2252-tree-transfer-engine/README.md), and [US-2253](../US-2253-drop-across-trees/README.md)

## Goal

Copy and cut board-tree items and paste them between supported local and board trees, preserving local OS clipboard interoperability and the reviewed transfer behavior.

## Background

`src/renderer/components/tree-provider/os-clipboard.ts` writes local hrefs with `api.clipboardWriteFilePaths`, reads `clipboardReadFilePaths`, and calls `copyPathsInto` for local targets. Its cut clear is conditional on Linux but unconditional on other platforms; asynchronous transfers can otherwise erase a newer clipboard. `src/ipc/contracts/clipboard.ts` has file-list and text-write endpoints, but no text-read endpoint. Clipboard history is optional and is not a reliable change counter. `src/main/system-clipboard.ts` already owns Electron text writes.

`ProviderItemController` in `src/renderer/components/tree-provider/provider-item-controller.ts` composes single and plural menus and calls `pasteIntoDir` in `item-crud-actions.ts`. `item-menus.ts` directly sends single local items to the OS clipboard, including root copy but excluding root cut; its file, folder and background Paste entries are local-only. `plural-actions.ts:buildMultiItemMenuItems` sends local selections directly and suppresses root cut. Copy Path/Href is separate text copying. `TreeProviderViewModel.ts:onKeyDown` handles Ctrl+C/X/V only for local providers and resolves root/folder/file-parent targets; it guards editable controls. `CategoryView.ts` forwards keys to `CategoryViewModel.ts:onKeyDown`, which currently handles Ctrl+A, Delete and Escape, **not** clipboard shortcuts; `src/renderer/editors/category/CategoryEditor.ts:categoryViewProps` enables its multi-select only for local providers. `ExplorerSecondaryView.ts:treeProps` enables tree multi-select. The controller fires `linkContextMenu` with the clicked item after building its menu; preserve this extension point and avoid duplicate actions in `src/renderer/ui/link-menus/tree-context-menus.ts`.

A board proxy retains private config and validated href/path maps; `ExplorerEditorModel.ts:ensureTreeProvider` and `dispose` dispose its provider when the page changes or closes. The US-2253 drag registry intentionally does not own a provider and cannot serve a persistent clipboard. US-2252 fixes `TreeTransfer.transfer({ provider, items }, { provider, folderPath }, { move, signal, onConflict, onProgress })`; a newly constructed proxy must list selected parents to rebuild its mapping. US-2253 supplies target resolution, OS-path source preparation, confirmation, conflict choices, cancellable progress, result summary and refresh. These are prerequisites, not new designs here.

## Implementation Plan

- [x] **Capability and owned lifetime - `src/renderer/content/tree-providers/tree-provider-capabilities.ts`, `ProxyTreeProvider.ts`, `tree-provider-factory.ts`, new `src/renderer/components/tree-provider/tree-clipboard.ts`.** Extend the US-2252 transfer capability with an internal source classification (`local` or `board`) and an explicit method to create an independent clipboard-owned source from the provider's already-validated construction data. Implement it at the provider/factory boundary, reusing `createTreeProvider` and the proxy's existing accepted-provider checks; do not derive credentials from `sourceUrl`, expose config to menus, serialize config to the OS clipboard, or retain the page-owned proxy. Snapshot selected links and their provider category paths in memory. On copy create a separate proxy, list each distinct selected parent and match each selected href against the fresh listing before use; retain only verified links, fail the operation clearly if any are missing or changed, and never guess paths from hrefs. Revalidate board ownership and service availability at paste; dispose the owned proxy on replacement, invalidation or full cut consumption, and after outstanding operations finish. Reference-count/lease an in-flight operation so replacement or page closure cannot dispose it mid-transfer. Clear on renderer shutdown; no persistence across app restart. Root rows are not ordinary listed items: disable board root copy/cut until the transfer capability can verify a root as a source; do not fabricate a parent mapping. Copy is available on readable transfer-capable board items including read-only boards; cut additionally requires writable source and deletion capability and excludes root. Same safety check applies at execution time.

- [x] **Clipboard arbitration - `tree-clipboard.ts`, `src/main/system-clipboard.ts`, `src/ipc/contracts/clipboard.ts`, `src/ipc/main/clipboard-handlers.ts`.** Board copy/cut writes selected item hrefs as newline-separated text through the existing `api.clipboardWriteText`; retain that exact text, a random generation ID, links, owned provider and cut flag in memory only. Per the roadmap decision, hrefs carry a connection key, never credentials; never write provider config. Add a small typed `clipboardReadText` endpoint through the existing `bindDomain` RPC and implement it beside `writeClipboardText` with Electron clipboard; no new message protocol or board bridge surface. At every paste select the in-app record only if the current OS text exactly matches its written text **and** the OS clipboard has no file list. Otherwise invalidate and dispose the record and use the current OS file list. Identical text without a live in-memory record cannot recreate a source. Copy Href of the same item produces identical text and therefore selects the in-app record; this is accepted. A local or external file list takes precedence even if its text matches. If writing or reading clipboard data fails, report failure and never use stale board data. Serialize this app's copy/cut writes and assign generation IDs before awaiting; publish only after successful text write, discard superseded preparations, and recheck generation, text and absence of files before starting paste. For external changes between comparisons and reading file paths, read the actual file list at the point of use; never reinterpret board hrefs as paths. Concurrent OS clipboard replacement is inherently not atomic with a transfer; after it starts, use its captured snapshot. Do not claim a read-then-clear sequence is atomic.

  ```ts
  // Before: local items -> copyPathsToOsClipboard(paths, cut)
  // After: local items -> OS file clipboard; board items -> owned source + href text
  // Paste: matching text and no files -> tree source; otherwise -> OS file list.
  ```

Prepare real OS paths using the US-2253 partition/list/dispose helper and preserve its aggregate cancellation and conflict behavior. Local to local still calls `pasteOsClipboardInto` / `copyPathsInto`. For an OS cut sent to a board, leave the OS clipboard intact after the move: the existing read and write endpoints cannot atomically compare and clear it, so a delayed clear could erase another application's newer content. ## Concerns / Open questions

The OS clipboard exposes the selected hrefs as useful text; those hrefs contain a connection key but never credentials, and provider config stays in memory. Copy Href of the same item yields identical text and intentionally retains the in-app record when no file list is present. The clipboard is renderer-session scoped and deliberately cannot be restored after restart. Clipboard comparison and a transfer cannot be atomic with an external application replacing clipboard contents; the captured operation completes, but must not consume the replacement. Root source transfer is unavailable until its source can be verified by the fixed engine contract. The capability implementation must validate accepted provider ownership again after re-creation and fail closed on unavailable services.

No new protocol, board-specific rule outside `src/shared/board/` and board registries, or `window.persephone` change is planned. If a bridge change becomes necessary, bump `BOARD_BRIDGE_VERSION` and add its history line. No `await import()` or wrapper to bypass import zones; fix dependency direction. `TreeProviderViewModel.ts` must shrink. Strict-folder changes must pass typecheck.

## Acceptance Criteria

- Board item copy/cut survives source page closure and transfers only verified items; unavailable sources fail visibly and safely.
- The in-app record is used only when the OS text exactly matches its href text and there is no OS file list; identical Copy Href text is an accepted match. Other clipboard content invalidates the record, and board transfers never clear newer OS content. Fully successful cut is consumed; partial cut is retained.
- All tree and folder view menu/keyboard paths use the correct target, capability and writable gates; local to local retains OS interoperability and its fast path.
- Shared US-2253 confirmation, conflict, progress, cancellation and results are used; no UI code deletes sources. Lint and typecheck pass; US-2256 covers the listed scenarios.
