# US-1563: Instant open — add the page before restore(), loading shell with Cancel, error and Retry, page.ready for scripts

**Epic:** [EPIC-116: Pipe status and instant open](../../epics/EPIC-116.md)  
**Status:** Done  
**Scope:** Fresh file opens whose editor model opts into deferred restore: file-backed text-host editors, ImageEditor, and content-host boards. All other editors keep restore-before-add. Show a generic page-level loading shell for opted-in editors using US-1561's expanded PipeStageListView, and preserve the current content-ready contract for script and MCP callers.

## Goal

Show a tab immediately for opted-in slow sources while their editor models restore behind a generic loading shell. Provide Cancel, an error with Retry for unexpected restore rejection, and a PageModel.ready promise that lets non-UI callers continue to wait until restore settles.

## Background

### Existing open and add order

- PagesLifecycleModel.createEditorFromFile() constructs the editor, assigns its pipe to the editor or adopted text host, seeds an explicit title, then awaits editor.restore() before returning (src/renderer/api/pages/PagesLifecycleModel.ts:255-290). openFile() calls that method, wraps the restored model, and only then calls addPage() (src/renderer/api/pages/PagesLifecycleModel.ts:587-620). Whole-pipe reads happen in TextFileIOModel.restore() (src/renderer/editors/text/TextFileIOModel.ts:235-313), ImageEditor.restore() (src/renderer/editors/image/ImageEditor.ts:109-168), and the adopted host used by BoardContentEditorModel.restore() (src/renderer/editors/board/BoardContentEditorModel.ts:143-163).
- addPage() currently invokes onPageCreated before it attaches the editor, then attaches it, inserts the page in the model, and immediately persists (src/renderer/api/pages/PagesLifecycleModel.ts:383-409). For a new page, attach the constructed editor before invoking the callback or inserting it; keep callback timing synchronous with page creation and document that content-dependent callback work awaits page.ready.
- The immediate-open path must seed filePath, a usable title, editor kind/icon state, source link, pipe descriptor, target editor, and any session context before adding the page. newTextFileModel(filePath) seeds the path but not the final basename title (src/renderer/editors/text/TextEditorModel.ts:466-475); image titles are set inside restore (src/renderer/editors/image/ImageEditor.ts:109-116). open-handler currently applies a link title only after lifecycle.openFile returns (src/renderer/content/open-handler.ts:67-71), so pass it into page construction before insertion. PageModel.title delegates to the raw main editor (src/renderer/api/pages/PageModel.ts:268-271).

### Editor restore inventory and cancellation

- **Text-host family (opt in):** TextHostEditorModel.restore() restores/adopts its TextFileModel and calls onHostAttached() (src/renderer/editors/base/TextHostEditorModel.ts:207-228); TextFileModel.restore() waits for TextFileIOModel.restore(), script restore, content detection, then sets restored (src/renderer/editors/text/TextEditorModel.ts:400-408). TextFileIOModel.restore() reads cache/source text and catches provider errors into providerError (src/renderer/editors/text/TextFileIOModel.ts:235-313). Add the signal only along this path through TextHostEditorModel.restore(options?), TextFileModel.restore(options?), TextFileIOModel.restore(options?), and IContentPipe.readText(options?). Keep the existing providerError and source-recovery behavior; a resolving restore hands control to the text editor's existing error/recovery UI.
- **ImageEditor (opt in):** restore() obtains a pipe, installs watches, reads bytes, builds a blob URL, and caches remote bytes; failures can use a disk-cache fallback and otherwise show a toast (src/renderer/editors/image/ImageEditor.ts:109-168). Pass the attempt signal to pipe.readBinary({signal}); keep the current toast/cache/error behavior. When restore resolves, mount ImageEditorView so its existing state/fallback UI owns the result.
- **BoardContentEditorModel (opt in):** restore() runs board validation then restores the adopted text host; its catch records contentHostError and resolves (src/renderer/editors/board/BoardContentEditorModel.ts:140-163). Pass cancellation into the host restore while keeping the existing contentHostError behavior. When restore resolves, mount BoardEditorView so its existing host error state owns the result.
- **Explicit opt-outs — keep restore-before-add; no edits for deferred open:** VideoEditor only prepares a stream session in restore(), without reading the whole pipe, so deferring gives no slow-read benefit (src/renderer/editors/video/VideoEditor.ts:303-307, 209-275); stream-host BoardEditorModel validates board metadata and clears transient state but does not read the page pipe (src/renderer/editors/board/BoardEditorModel.ts:909-944); BoardInfoEditorModel restores optional host/properties data for its own board-info view, not a slow file-open pipe (src/renderer/editors/board-info/BoardInfoEditorModel.ts:331-356); ArchiveEditor initializes its tree provider/panel, not page-pipe bytes (src/renderer/editors/archive/ArchiveEditor.ts:92-106); GitTreeEditorModel synchronizes Git state (src/renderer/editors/git-tree/GitTreeEditorModel.ts:191-194); ToolsetEditorModel reads its local manifest (src/renderer/editors/toolset/ToolsetEditorModel.ts:93-117); MnemeRootEditorModel resolves its tree root (src/renderer/editors/mneme-root/MnemeRootEditorModel.ts:207-222); CategoryEditorModel inherits the base no-op restore (src/renderer/editors/base/EditorModel.ts:140-146). These do not receive a shell or cancellation changes.
- **Pipe consumers outside editor restore():** board pipe handlers accept a signal and forward it to pipe.readBinary()/pipe.stat() (src/renderer/editors/board/board-pipe-handler.ts:49-52, 76-83, 132-181). Board resource loads remain independently cancellable. Link editor image tiles read a separate archive pipe (src/renderer/editors/link-editor/pipe-image-src.ts:43-79), not the newly opened page's pipe, and are unaffected.

The content APIs already have an abort path for binary reads and streams: ContentPipe.readBinary(options.signal) forwards it through provider and transformers, while readText() currently accepts no options (src/renderer/content/ContentPipe.ts:108-141). Add an optional signal options parameter only to readText(), the opted-in text-host restore chain, and ImageEditor.restore()'s pipe.readBinary() call. EditorModel.restore() is declared with no required arguments (src/renderer/editors/base/EditorModel.ts:140-146); make its new options parameter optional so existing restore() overrides that take no arguments remain valid and unchanged. BoardContentEditorModel passes options only to its adopted host restore.

### Session restore, Retry, and settled design

- Startup session restore is intentionally **unchanged**. PagesPersistenceModel.restorePage() constructs and restores each editor before returning a PageModel (src/renderer/api/pages/PagesPersistenceModel.ts:180-313); applyState() waits for every page, then attaches/inserts them together (:381-415). A page saved mid-load from a slow source still delays its own restore at next launch exactly as today; the startup flow does not expose a loading shell.
- Add a per-page attempt state and ready: Promise<void> to PageModel. For an opted-in editor, ready resolves when its existing restore() settles, including when it records a handled provider error and resolves; ready rejects only when restore() rejects unexpectedly. For opt-outs, ready is already settled before addPage(). Every Retry creates a new attempt promise/controller and updates the page's current ready; attach an internal rejection observer so UI-only opens do not produce unhandled-rejection warnings while callers awaiting the promise still receive rejection.
- Loading shell: create a coupled page component under src/renderer/components/pipe-status/ that consumes US-1561's exported PipeStageListView at expanded density, page pipe status, and the page attempt state. PageContentView owns the transition between shell and RenderEditorView. Cancel aborts first, then closes/removes the page. Error keeps the page and shows Retry.
- Retry: only the loading shell handles a rejected restore promise. Dispose that failed editor model, rebuild the pipe from the page's persisted sourceLink/pipe descriptor with pipeFromPersistedSource (src/renderer/content/rebuild-pipe.ts:74-91), construct a fresh editor through the same opt-in construction path, attach it as the same page's main editor, and start a new attempt. Do not invoke restore() twice on one model; editor-owned handled errors continue to use each editor's existing recovery path.
- Script compatibility: PagesModel.openFile() must resolve the opened/deduped page and await its ready; PageCollectionWrapper.openFile() and its AiVision method inherit that wait. app.openRawLink() and script app.events.openRawLink.sendAsync() must await ready for script-originated raw-link events, while ordinary UI openRawLink clicks resolve after page insertion. Existing page.content, editor facade calls, and page.grouped reads/writes therefore observe restored state after their opening calls complete.
- Design decisions 5 and 6 in EPIC-116 are settled: use one generic shell for opted-in editors and keep script/MCP opens waiting. Deferral is opt-in through an instance flag on EditorModel: default false, overridden only by the TextHostEditorModel file-host path, ImageEditor, and BoardContentEditorModel. These models are constructed through PagesLifecycleModel's built-in/board factory branches (src/renderer/api/pages/PagesLifecycleModel.ts:179-250), while editor modules are registered with EditorDefinition and their factories (src/renderer/editors/base/editorRegistry.ts:24-45, 64-84). VideoEditor, stream-host BoardEditorModel, BoardInfoEditorModel, ArchiveEditor, GitTreeEditorModel, ToolsetEditorModel, MnemeRootEditorModel, and CategoryEditorModel explicitly opt out and retain restore-before-add for the reasons listed above.

## Implementation Plan

1. **Add explicit model opt-in and branch the open flow.** In src/renderer/editors/base/EditorModel.ts, add readonly deferRestoreOnOpen = false. Override it to true only in the file-backed TextHostEditorModel path, ImageEditor, and BoardContentEditorModel; keep BoardEditorModel's stream-host default false. In src/renderer/api/pages/PagesLifecycleModel.ts, preserve the current restore-before-add path for false. For true, construct and seed the model/pipe/source metadata, add the page, then start restore in the background. Keep createEditorFromFile()'s ready-before-return behavior for PageNavigator and other non-fresh-page callers. Seed basename/title before add for the opted-in paths.

   Split construction from restoration so the existing `createEditorFromFile()` contract remains ready-before-return for callers such as PageNavigator. In `openFile()`, branch after constructing and seeding the model:

       const editor = await this.constructEditorFromFile(filePath, pipe, options);
       if (!editor.deferRestoreOnOpen) {
           await editor.restore();
           return this.addPage(wrap(editor), undefined, options?.onPageCreated);
       }
       const page = this.addPage(wrap(editor), undefined, options?.onPageCreated);
       this.startRestore(page, editor, pipe);
       return page;

   `constructEditorFromFile()` is a proposed extraction of the construction and pipe/title setup currently inside `createEditorFromFile()`; it does not restore. Keep the current method as construct + `await restore()` for its existing callers. The opted-in path alone inserts before starting restore.

2. **Add PageModel readiness and attempt ownership.** In src/renderer/api/pages/PageModel.ts, add a current ready promise, a fresh AbortController per restore attempt, a guarded attempt identity, and methods to start/retry/cancel restore. Reject readiness on a real restore failure; resolving after a stale/canceled attempt must not replace a newer attempt state. Make dispose() abort its active attempt before releasing editors. In src/renderer/api/pages/PagesLifecycleModel.ts, preserve onPageCreated callback access to the attached editor/page before insertion, then attach lifecycle state and begin restore immediately after insertion.

3. **Render the shell and gate consumers.** Add src/renderer/components/pipe-status/PageLoadingShellView.ts and its co-located stylesheet (or the equivalent page-owned component in that folder). Update src/renderer/ui/app/PageContentView.ts to subscribe to the page attempt state, show the shell instead of RenderEditorView, then mount the normal editor only after readiness. Do not mount content-dependent secondary panel views until ready; retain sidebar width/open state. Subscribe/dispose with the page view lifecycle and correctly rebind on page/editor replacement.

4. **Thread cancellation only through the opt-in pipe reads; preserve all editor error behavior.** Add an optional { signal?: AbortSignal } parameter to ContentPipe.readText() in src/renderer/content/ContentPipe.ts. ## Concerns

- TextFileIOModel.restore(), ImageEditor.restore(), and BoardContentEditorModel.restore() deliberately handle provider failures through providerError/source-recovery, toast plus cache fallback, and contentHostError respectively (TextFileIOModel.ts:300-311; ImageEditor.ts:153-168; BoardContentEditorModel.ts:156-163). Do not convert those handled failures into rejections: source-recovery.ts and each editor's current error UI/recovery would be bypassed. When these restores resolve, page.ready resolves and the shell mounts the editor; the editor owns its existing error UI. The shell's error and Retry appear only for an unexpected rejection from restore().
- Only opted-in editors become visible before restore. Seed stable identity and persist replayable source state before insertion; do not mark text content restored or modified prematurely. Startup restoration remains ordered before insertion, so a session descriptor captured mid-load must be valid in the existing restorePage() path.
- Retry is for an unexpected rejected restore, not editor-owned provider errors. Dispose the failed editor model, rebuild a pipe with pipeFromPersistedSource from the persisted descriptor/sourceLink, construct a fresh editor, and attach it to the same page. Do not call restore() a second time on the failed model.
- onPageCreated currently runs before editor attachment. Changing it to run after attachment is needed for an inspectable loading page but is observable callback timing; audit its concrete board capability-handler use and keep callback invocation synchronous.
- Stream-host boards and VideoEditor opt out because their restore work does not wait on whole-pipe reads, so page-close cancellation is outside this task's deferred-read path.
- Editor switches and script operations can be invoked through public APIs before the shell completes. Gate operations that require restored content on page.ready; UI toolbar switch controls are naturally absent while the shell is mounted.

## Acceptance Criteria

- A fresh UI file open whose model opts in inserts a page with file path, title, icon/editor identity and source descriptor before restore finishes, and shows the tab immediately. Opt-out models keep restore-before-add.
- While an opted-in restore is pending, the page shows the generic shell with US-1561's expanded stage list and Cancel. The editor view and content-dependent secondary panels do not mount until restore settles; if the editor handles a provider error and resolves, its own error UI appears after handoff.
- Cancel and closing an opted-in loading page abort the current text/image read where supported, discard late results, close the page, and prevent that page from being persisted as open.
- If an opted-in editor's restore unexpectedly rejects, the page stays visible with a useful shell error and Retry. Retry disposes that editor model, rebuilds the pipe from persisted source state, creates a fresh editor model, and starts a new attempt on the same page.
- Handled provider failures retain current editor behavior: restore resolves page.ready, then the shell mounts the editor and its providerError/source-recovery, toast/cache fallback, or contentHostError UI appears.
- PageModel.ready resolves/rejects for the current opted-in restore attempt and is settled before opt-out pages are added. Opted-in UI opens return after page insertion; script/MCP pages.openFile, app.openRawLink, and app.events.openRawLink.sendAsync preserve their existing wait-until-restore-settles behavior.
- Double-opening an opted-in file while its first restore is in flight reuses one page and runs one initial restore. Single-instance board opens reuse the early content-host board page; existing onReopen behavior remains for ready pages.
- New-page navigation hints for opted-in pages are applied once after restore settles. Opt-out opens and existing-page navigation keep their current restore-before-add/swap ordering.
- Saving a session while a page is loading writes a descriptor that reopens correctly on next start. Session restore remains restore-before-add.
- No editor performs partial rendering. **Opted in:** text-host file editors, ImageEditor, BoardContentEditorModel. **Opted out:** VideoEditor (stream-session setup, no whole-pipe read); stream-host BoardEditorModel (no whole-pipe read); BoardInfoEditorModel (its host is auxiliary board-info state); ArchiveEditor (tree/panel setup); GitTreeEditorModel (Git-state sync); ToolsetEditorModel (local manifest read); MnemeRootEditorModel (tree-root resolution); CategoryEditorModel (base no-op restore). Each opt-out keeps restore-before-add and needs no deferred-restore edit.
- No unit tests are added.

## Implementation notes

- No plan deviations or additional editor opt-outs. The text-host family, ImageEditor, and
  BoardContentEditorModel opt in; every listed opt-out keeps restore-before-add.
- Public script `page.ready` is exposed through the page wrapper. Fresh navigation line and text
  hints also wait for the current restore attempt before being applied.
- **Review fixes (2026-09-29; not live-verified):** image restore now exits quietly when its
  signal is aborted; text and image discard source results that arrive after cancellation; and
  cancellation rejects the current `page.ready` promise promptly even when a provider ignores
  the abort signal.
