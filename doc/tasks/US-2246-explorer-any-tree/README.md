# US-2246: Explorer shows and persists any tree

## Goal

Make the Explorer panel show, navigate and restore a factory-created tree, including the board-backed proxy in [EPIC-217](../../epics/EPIC-217.md). Keep local Explorer behavior intact and make slow, failing and unavailable trees understandable and recoverable.

## Background

- The reviewed [US-2243](../US-2243-tree-provider-factory/README.md), [US-2244](../US-2244-board-tree-service-api/README.md) and [US-2245](../US-2245-proxy-tree-provider/README.md) plans are prerequisites and contracts; reconcile their final exports, not their intended semantics, before implementation. US-2245 supplies an inert proxy shell even when a board is missing, opaque config, stable `sourceUrl`, root-safe child joining and a case-sensitive path-to-href index. It exposes no search, `addItem`, `importFiles`, or `importLinks`; its optional writes reflect current capabilities.
- `ExplorerEditorModel.ts` subscribes only to local `rootPath`, constructs a typed `TreeProviderHost<FileTreeProvider>`, compares `sourceUrl` to that path, and returns early in `listItems` without a root. `ExplorerSecondaryView.ts` also assumes a file provider and compares its `sourceUrl` with a local path. A board proxy's `sourceUrl` is descriptor identity, not root path or a board href.
- Persistence is already page-owned: `PageModel.getDescriptor()` serializes **all** editors using `getRestoreData()`; `PagesPersistenceModel.saveState()` writes those descriptors and `constructPage()` uses `editorRegistry.restoreFromDescriptor`. `editors/explorer/index.ts` has the restore-only factory. `skipSave` concerns editor content saving, not page descriptor serialization. `sidebar` stores open/width/active panel only. `getRestoreData` already spreads state and persists expansion, selection and search; `applyRestoreData`, `restore`, and `setPage` require adjustment for a descriptor even with an empty legacy root. Existing local and legacy underscore extras must still restore.
- `ProviderTreeStore.buildTree` lists the root; `loadChildren` catches lazy-load errors and replaces them with `[]`. `TreeProviderViewModel.buildTree` puts root errors in `state.error`, rendered by `TreeProviderView.showMessage`; a null tree currently displays `mneme.noContent`, including while loading. `registry.ts` provides `isProviderResolutionError`, `subscribeProviderAvailability` and a descriptive `MissingProviderError`/`ProviderUnavailableError` message. `source-recovery.ts` reports this text as a toast. A literal reusable **Provider missing** panel label does not exist: the guide uses that phrase, while the implementation supplies the typed error and guidance. Reuse the existing error panel and error detail, adding a localized title.
- `tree-provider-capabilities.ts` already owns `isLocalFileProvider`; use this existing helper, not a second `type === "file"` check. `href-utils.ts` uses platform case for every href, causing Windows remote collisions. `boardSchemeOwner` and `schemeOf` are exported from `src/renderer/content/scheme-registry.ts`; the components import zone permits this direct content import (the restricted components zones concern imports from editors, scripting and shell UI). Remote hrefs are opaque and cannot be turned into board paths with filesystem functions.

## Concerns

- Tree href and board path are different namespaces; category+title or the proxy's indexed mapping supplies paths. A URL cannot be decoded by core. A previously unknown href cannot be revealed until indexed; return a clear failure instead of inventing a mapping.
- Different-source board/local tree and OS-file drops are already rejected by the proxy's ILink-only drag and lack of import methods. Same-source board moves enter the existing move branch but cannot safely pass an opaque href to path-based `rename`; this plan refuses them pending roadmap phase 2.
- Provider availability is signaled before claims finish rebuilding; deferred and disposal-guarded retry is required. Config is opaque persisted JSON and must not contain credentials (epic decision 5).
- No design question remains for implementation; prerequisites must land first. US-2247 owns board `openTree`, US-2248 owns the test board and UI tests, US-2249 owns guides and epic-close translations.

## Acceptance Criteria

- [ ] Existing local sessions and Explorer actions remain unchanged; a descriptor-backed Explorer and its expansion/selection restore with the page across restart, including when its provider is missing.
- [ ] Missing/untrusted or unavailable providers show **Provider missing** and existing explanatory detail; refresh after trust/installation recovers, and disposal removes subscriptions. Ordinary failures remain distinct and retryable.
- [ ] Root and individual folders show loading; nested failures remain visible and retry successfully; collapse, replacement and disposal ignore stale results, including concurrent folders.
- [ ] Board navigation uses board paths and preserves descriptor/config; local-only controls and programmatic entry points cannot operate on remote paths. Correct provider capabilities govern write menus.
- [ ] The three cross-tree/OS drop cases remain refused by existing trait and capability checks; same-source board moves are refused cleanly. Case-distinct board-owned hrefs remain distinct on Windows, while local and built-in scheme comparisons retain today's behavior.
- [ ] Explorer scripting/MCP list, open, reveal and expand/collapse honor the stated path and href contracts; board reveal works for loaded/indexed hrefs and clearly fails for unknown hrefs; `workspaceFolder` remains local-only. Required checks pass and Claude's live results are recorded; no unit tests.
