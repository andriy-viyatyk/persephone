# UI integration tests

The UI suite is a locally run, scripted smoke check for regressions. Plain Node scripts drive a separate Persephone through the same call tree as agents; no LLM, unit-test framework, screenshot baselines, or CI desktop is required. Run it on a desktop with the dev target; Claude can run it there, while Codex cannot launch Persephone in the restricted environment.

## Layout and isolation

`integration-test/run.mjs` orchestrates; `lib/` owns launch, MCP, test context and reporting. `seed/` is committed profile data; `fixtures/` is committed sample input; `fixtures/http/` contains read-only HTTP inputs; tests live at `tests/<area>/<module>/<feature>.test.mjs` with deeper module subfolders allowed. A test's area/module id is its path under `tests/` without the filename, such as `core/smoke` or `editors/grid/sort`. `.profile/` and `reports/` are generated and ignored. Each normal invocation resets `.profile` from the seed and copies fixtures into `.profile/work`; tests must edit only work copies. Attach refreshes fixture copies over existing copies while preserving other work files. The identity is `uitest`, with MCP 17865, video 17866, Mneme 17700, Tor 19052 and HTTP fixtures 17867, distinct from the normal app. Port, pipe and lock checks protect the profile; do not bypass them. A test restart preserves the current run's state; a new normal invocation resets it.

## Run and investigate

Start `npm start`, then `npm run test:ui`. Use `-- --area <path-prefix[,path-prefix]>`, `-- --test <name substring>`, `-- --timeout-scale <positive number>`, `-- --keep-open`, `-- --rerun-failed`, or `-- --with network,mic`. Area selection is a whole-segment path prefix: `core` selects `core/smoke` and `core/settings`, but not `core-x`; `editors/grid` selects that module and submodules. Each requested prefix must match a module or the runner errors before profile reset and lists known module ids. Requirement tags are `network`, `mic`, `tor`, `git`, `mneme`, and built-in `launch`; every external tag declared by a test must be opted into, otherwise that test is skipped with a reason. `--with` rejects `launch`. Reports count passed, failed and skipped separately, and only failures enter `last-failed.json`. If a saved failed ID has moved or disappeared, `--rerun-failed` reports it as gone and continues with current failed IDs. `--keep-open` retains a healthy test app only after failure. Reports are `reports/latest.md`, `latest.json` and `last-failed.json`, with failure screenshots when available. Inspect failing entries first. `npm run test:ui:call -- <path> '[args]' [--text] [--dialog] [--max-length N]` targets the test MCP URL; `--dialog` opts into the pilot's modal handling. `npm run test:ui:call -- window.screen.screenshot '[]'` saves a screenshot; `npm run test:ui:call -- --close` shuts the retained instance down. Close before a normal rerun because it resets the profile; attach runs can reuse the retained app. The ordinary agent MCP connection targets the user's app, not the test app. Main-process changes require a new test instance; renderer changes hot-reload.

`--list` prints the area/module tree and test counts without starting an app or taking the runner lock; use `--area` to narrow it. It rejects `--open`, `--keep-open`, and `--rerun-failed`. `--with` and `--attach` determine the displayed skipped-by-requirements counts. Normal test runs stop the app, re-seed the profile, and start it again between module ids. Keep each module below about 50 tests and about 3 minutes; split by feature into submodules such as `editors/grid/sort`, never by test count. Append tests to the module that owns the feature. Add a module folder for a feature without an existing owner; add a new area only with a new roadmap phase.

`--open` resets the isolated profile, starts the selected target, writes `reports/keep-open.json` and exits without running tests or replacing reports. It accepts `--prod`, `--app` and `--timeout-scale`; close the app with the existing call CLI. `--attach` uses that retained record and app, takes the runner lock, refreshes fixture copies, starts the HTTP service and runs selection without resetting, launching, restarting or stopping the app. It accepts area/name/failure selection, requirements and timeout scale, but no target override or keep-open. Attach reports identify target `attach`. The HTTP fixture service binds to `127.0.0.1:17867` only during test runs and remains active across normal app restarts; neither open nor retained failure apps keep it alive.

Run the suite when asked. The default target is `dev`; `npm run test:ui -- --prod` and `npm run test:ui -- --app "C:\path with spaces\persephone.exe"` are optional draft-release post-checks, never mandatory release steps. These targets are mutually exclusive. `--prod` rebuilds `.vite/build` once, refuses a live dev marker, and prints `The dev bundle was replaced; run npm start again before dev tests.` after the build exits. Restart `npm start` before using dev mode again. `--app` directly owns the supplied compatible installed or unpacked executable, which must include US-2022 `--profile-dir` support. Reports record the selected `dev`, `prod`, or `exe` target; exe selections also retain the absolute path. `--keep-open` keeps the owned instance open only after failure and records its real child PID and isolated profile, including for exe mode; use `npm run test:ui:call -- --close` before rerunning.

## Add a test

Default-export one descriptor or an array from `tests/<area>/<module>/<feature>.test.mjs` using `test(name, async ctx => {})` from `lib/context.mjs`. `ctx.call(path, args, options)` parses structured primary results; `ctx.callText` preserves exact text, including JSON-looking strings. Omit args for property reads and pass `[]` for zero-argument methods. `ctx.waitFor(pathOrFn, predicate, { timeout })` polls until the predicate passes; it does not retry call errors. Do not add fixed sleeps. `ctx.expect` offers `toBe`, `toEqual`, `toContain`, and `toBeTruthy`; `ctx.script` and `ctx.restartApp` cover completed scripts and owned-process restarts. Follow the pilot and runner README for dialog options.

Use `ctx.fixture(relativePath)` to obtain a validated work-copy path. Reset mutable fixture content with `ctx.call('fs.write', [path, content])` at the start of each test; save changed pages and close them via `pages.closePage`. Tests must run independently and leave committed fixtures unchanged. Tests share no state, each test closes the pages it opens, and files it creates go under a per-test folder in `ctx.fixture`, especially when authoring for attach runs. Store text fixtures as UTF-8 without BOM, with LF and a final newline; use explicit `\n` in test data.

Cross-area steps belong in `tests/helpers/`; area-only steps belong in `tests/<area>/helpers.mjs`. Promote an area helper only after another area uses it. Do not move an area's setup into the cross-area folder preemptively. Use `ctx.httpUrl("/path?query=value")` for HTTP fixture URLs. It accepts only local paths beginning with one slash. Static files from `fixtures/http/` support GET/HEAD, return `text/plain; charset=utf-8`, 404 when missing and 405 for unsupported methods. Routes are `/echo` (any method; JSON `{ method, url, headers, body }`, UTF-8 body, maximum 1 MiB), `/delay?ms=N` (GET/HEAD, `delayed`, 0–5000 ms), `/status?code=N` (GET/HEAD, status 200–599), and `/redirect?to=%2Fpath&status=302` (GET/HEAD, local path and status 301/302/303/307/308). Invalid values and unsafe paths return 400; oversized echo returns 413. Dynamic plain text uses `text/plain; charset=utf-8`; echo uses `application/json; charset=utf-8`; redirect responses use `Location` without a body.

Tests that use `ctx.restartApp()` or `ctx.launchSecondInstance(args = [])` declare `requires: ["launch"]`. Second-instance tests may pass no arguments or a file path already created under `ctx.fixture(...)`; process exit confirms handoff only, so poll the primary app with `ctx.waitFor`. Both helpers give an author-facing error in attach mode; attach never starts or restarts the app.

When the call tree cannot reach a needed UI element or action, record the gap and fix the tree at its owning node or `data-name` contract. Do not bypass the missing tree surface in a test. Run the relevant area and then the full suite; investigate failures instead of weakening assertions.
